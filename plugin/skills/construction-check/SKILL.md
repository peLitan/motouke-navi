# 建設の書類の点検(Motouke Navi)

はじめて元請けをする会社が、施工体制台帳などの書類を出す前に、抜けや食い違いに気づくための点検です。
結果は「候補」です。法令の判断や役所の判断ではありません。最後は人が原文と書類を見て決めます。

## 守ること

- 書類は `raw/` から直接読まない(Read・Grep・Bash の cat なども使わない)。道具 `masked-files` の `read_masked` に `raw/` からのパスを渡し、置き換えた後の中身だけを読む。フックが `raw/` を指す操作を止めるが、フックで止められない操作もあるので、自分でも読まない
- 中身の〔会社名1〕〔人名2〕のような記号は、元の名前に戻そうとしない。推し量った名前を書かない。指摘にも記号のまま書く
- 根拠にしてよいのは、このスキルの `reference/sources/` にある取得した条の原文だけ。`reference/articles.md` の「取得した条」の一覧にない条は、覚えている中身で根拠にしない。要る場合は「見ていない条なので確かめられない」と書き、人に回す
- 「違反です」「必ず」「保証」と言い切らない。原文の条件に当てはまるかが書類から分からないときは「判断できない(○○が書類に無い)」と書く
- 外へ送らない。道具は手元で動く

## 手順

1. 点検する書類を決める。利用者が示したパスを使う。書類の名前が分からないときは `list_masked` で `raw/` の中のファイルの名前の一覧を見て(中身は返らない。`ls` などはフックで止まる)、点検する書類が1つに決まらなければ利用者に聞く
2. `read_masked` で書類を読む。読めない形(画像の PDF など)は、読めなかったと伝えて止まる
3. 書類の種類と、工事の前提を書類から拾う。拾えないものは「書類に無い」として残す(推測で埋めない)
   - 発注者から直接請け負ったか(元請けか)
   - 公共工事か民間工事か
   - 下請契約の請負代金の額(合計)、建築一式工事か
   - 許可の種類(特定・一般)と業種
   - 工事一件の請負代金の額、施設や工作物の種類(専任が要るかに関わる)
4. `reference/articles.md` の各条の要約で、どの条が関わりそうかを当たりを付け、`reference/sources/` の原文で条件を読む(要約は入口で、根拠は原文)
5. 指摘を1件ずつ書く。形は下の「指摘の書き方」
6. 指摘の文(全件。記号のまま)を道具 `masked-files` の `check_articles` の `text` に渡し、条番号を確かめる。指摘はファイルに保存しなくてよい

   - 「無い」と出た条番号は、条・項・号の書き間違いか、取得していない条。原文を見直して直すか、根拠から外して「見ていない条」として人に回す
   - 「確かめられない」は法令名が無い書き方(「法第○条」「同条」など)。法令名から書き直す
   - 道具が確かめるのは、その条・項・号・細分が取得した原文にあることだけ。指摘の中身が条の文に合っているかは確かめないので、自分で原文と見比べる
   - 道具を呼べなかったときや、道具が「どの条番号も確かめていません」と返したときは、飛ばして進まず、手順 9 で「条番号を確かめていない」と書く
7. 反証の係 `refuter` に候補を見直させる。Agent の道具で呼び(プラグインから入れたときの名前は `motouke-navi-guard:refuter`)、次の3つを渡す
   - 点検した書類の `raw/` からのパス
   - 指摘の一覧(全件。記号のまま)
   - 根拠にした条の原文の抜き書き(`reference/sources/` から一字一句写す。係は原文のファイルを開けない)

   係を呼べなかったときは、飛ばして進まず、手順 9 で「反証の見直しをしていない」と書く
8. 係の結果を指摘に反映する
   - 「残る」: そのまま残す
   - 「確かめられない」: 指摘の一覧から外し、「外した候補」に係の理由とともに移す。ただし理由が「渡されていない」なら、足りない物を渡して1回だけ呼び直す
   - 「崩れた」: 係の「直すなら」のとおりに確かさを下げるか根拠を外す。直せなければ「外した候補」に移す
   - 係が新しい点を挙げたら、指摘に混ぜず「係が足した点」として別に並べる(見直しを受けていない)
   - 外した候補は消さない。「確かめられない」は誤りと決まったのではなく、最後は人が見る
   - 指摘を直したら、手順 6 の `check_articles` をもう一度呼ぶ
9. 利用者に、指摘の一覧、`check_articles` の結果(ある・無い・確かめられないの数)、係の結果の数(残る・崩れた・確かめられない)、外した候補をそのまま見せる。見ていない条に関わる点は、別に並べる

## 指摘の書き方

1件ごとに次を書く。

- 何が: 書類のどの欄・どの行か(記号のまま)
- どう見えたか: 書類に書いてあること(または書いていないこと)
- 根拠: 法令名を省かずに、条・項・号まで(例: 建設業法第24条の8第1項、建設業法施行規則第14条の2第1項第3号ハ)。原文の短い抜き書きを「」で添える(原文と一字一句同じに。言い換えない)
- 確かさ: 「当てはまる」「当てはまるおそれ」「判断できない(何が分からないか)」のどれか
- 人がすること: 確かめる書類や、聞く相手(発注者・下請負人など)

書き方の例(架空):

> - 何が: 施工体制台帳の下請負人〔会社名2〕の健康保険等の加入状況の欄
> - どう見えたか: 欄が空
> - 根拠: 建設業法施行規則第14条の2第1項第3号ハ「健康保険等の加入状況」
> - 確かさ: 当てはまるおそれ(台帳を作る義務がある工事かは、下請契約の額が書類に無いので判断できない)
> - 人がすること: 〔会社名2〕に加入の状況を聞き、欄を埋める

## 点検で見る所の目安

条の要約と見ていない条は `reference/articles.md`。主に次を見る。

- 施工体制台帳を作る・備えるか(建設業法第24条の8、建設業法施行令第7条の4、公共工事は入札契約適正化法第15条)
- 台帳の記載事項と添付書類の抜け(建設業法施行規則第14条の2)
- 再下請負の通知(建設業法第24条の8第2項)
- 主任技術者・監理技術者の置き方と専任(建設業法第26条、建設業法施行令第27条)
- 許可の区分と下請契約の額(建設業法第3条、建設業法施行令第2条)

金額の境目は原文の数字を使い、覚えている数字を使わない(法令は改められることがある。取得日は `reference/sources/index.json`)。

## このスキルでできないこと

- 取得していない条(`reference/articles.md` の「見ていない条」)に関わる判断
- 書類が本物か、書かれた内容が事実か(許可や資格を役所の名簿と照らすことなど)
- 置き換えの漏れを見つけること。置き換えには漏れがあり、0にはならない。元の名前らしい語が見えたら、利用者に知らせる(その語を繰り返し書かない)
