# 3分の動画の台本

- 長さ: 12場面で合計 2:58(審査の上限の 3:00 以内)。9 は Claude Code の場面で、9a〜9e に分けた
- 始まり: スライドは使わず、0:00 から画面を映す。人の話は声と字幕で乗せる
- 映すもの: このリポジトリで期間中に作った物だけ。見本の工事・会社・人はすべて架空で、鍵や個人の情報は映さない
- 声は作者本人が読む。読み原稿の合計は 698 字(600〜700字に収める)
- 字幕は1行13字以内・2行まで、表示は「字数÷4」秒以上
- Claude の動きは毎回違う。端末の場面が台本と違ったときは、映った結果に合わせて読み替える(結果を作らない)

## 場面の補足

- 3: 根拠を開くと「建設業法 第24条の8第1項」の見出しが2回続けて見える。同じ項から抜き書きを2つ取っていて(前半の作る義務の条件と、後半の「施工体制台帳を作成し」の文)、抜き書きごとに見出しを出すためで、表示の誤りではない。2つの抜き書きが映るまで止める
- 4: 見本の値から、発注者・請負代金・下請けの総額を変える。許可と工事の種類は見本のままでよい
- 5: 入札前の確認の欄は「仮の一覧です」と出るので、施工体制台帳の欄を映す
- 7: 貼る文は「現場代理人 甲野太郎。架空土木株式会社と、ためし鳶に足場を頼みました。」。後の欄は「現場代理人 〔人名1〕。〔会社名1〕と、ためし鳶に足場を頼みました。」になり、「ためし鳶」が残る
- 8: 混ぜる見本の語は、毎回選び直す。見つけにくい型の ○ は引いた型で変わるので、撮ったときの実際の数を映す(手で書き換えない)。見つけやすい型が 6/6 でも、見本は道具が扱う形から選んでいるので、7 のような漏れが無いという意味ではない。見つけにくい型の結果は漏れの目安で、保証ではない
- 9a: 作業フォルダには `plugin/evals/cases/E1_しおかぜ町下水道/raw/` だけを写す。点検を頼む `prompt` を貼るだけでは Claude が最初から `read_masked` を使い、`Read` が止まる所は映らないことがある。人が画面で頼んで確かめた流れと同じく、録画では「raw/施工体制台帳.md を Read で開いて」とそのまま打つ
- 9c: ここで初めて `case.json` の `prompt` を貼る
- 9d: 10件と1件は、架空の台帳で確かめたときの数。外した1件は反証で崩れたのではなく「確かめられない」としたもので、崩した件数は言い切らない。録画の数が違えば、映った数に読み替える
- 9c〜10: 端末は早送りし、字幕の右上に「早送り」と出す(実際の長さを隠さない)
- 11 の仕込み: [docs/評価.md](評価.md) の点検の結果。見つけた 9・見落とし 2
- 11 の漏れ: [docs/mask-rate.md](mask-rate.md) の 2026-11-04 の測り直しの、初めて見る書類4件・98語で辞書に足さない場合の 37.8%。人名・現場名を辞書に足すと 14.3%。2026-11-04 朝に commit 520ced6 で測った値で、そのあとの置き換えの直し(F31・F36)では測り直していない
- 11 の条番号: 条番号が取得した原文にある割合。プラグインありは 72.9%、なしは 47.1%。各6回だけで、なしは取得していない条を正しく挙げても外れに数えるので、プラグインの側に有利な数え方
- 11 の見落とし: ありの見落とし5件は、ファイル名が分からず点検を始めずに止まった1回(E1 の3回目)のもの。その1回を除くと差が出ていないので、字幕にそう添える
