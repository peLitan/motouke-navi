# 3分の動画の台本

- 長さ: 3分以内(下の時間の合計 2分50秒)
- 映すのは、このリポジトリで期間中に作った機能だけ(`index.html` の画面、`tools/claude-check.mjs`、`docs/`)。開始前に用意した開発の仕組み(自走キット)と設計の文書は映さない
- 見本の工事・会社・人・番号はすべて架空。実際の工事の書類や、氏名・鍵などは映さない
- Claude の API に送る場面は、鍵を映さない。送る中身の表示までを映し、送った結果は利用者が本物の API で確かめたもの(F12b)ができてから差し替える。それまでは送る手前で止める

| 時間 | 映すもの | 話すこと |
|---|---|---|
| 0:00〜0:15 | `index.html` を開いた画面 | 中小の建設会社の担当者は、入札のたびに「台帳は要るか」「監理技術者か」を条文で確かめています。この道具は、それを原文の抜き書きつきで出します。ブラウザで開くだけで、外へは通信しません |
| 0:15〜0:45 | 「見本で試す(架空の工事)」を押す → 「入札前の確認」と「施工体制台帳が要るか」の結果 | 架空の工事の条件を入れました。受注したら要るものが、建設業法の何条かと原文の抜き書きつきで出ます。金額の境目もコードに書かず、取得した原文から読んでいます |
| 0:45〜1:00 | 請負代金・下請けの総額を変えて「確認する」を押し直す | 下請けの総額を変えると、監理技術者か主任技術者かが変わります。決められないときは「判断できない」と出し、推測で埋めません |
| 1:00〜1:20 | 受注後の段取りの一覧(着手まで・施工中・完成・引き渡し) | 受注後は、土木工事共通仕様書のどの条で、いつ・何を・誰に出すかを一覧にします。国の直轄の例で、自治体や民間は発注者の仕様書で置き換えます |
| 1:20〜1:45 | 「2. 施工体制台帳の点検」の候補(主任技術者の欄が空の下請けなど) | 台帳を貼ると、抜けや食い違いの候補を根拠つきで出します。国交省の作成例の Excel もそのまま読めます。読めない欄は理由をつけて出します |
| 1:45〜2:00 | 「3. 施工計画書の目次の点検」の候補と注意 | 施工計画書の目次は、共通仕様書の16の記載事項と比べ、見当たらない項目を出します。合否ではなく候補です |
| 2:00〜2:25 | 「A. 文の置き換え」の前・後・対応表 → 「元に戻す」 | 外の AI に貼る前に、人名や会社名を記号に置き換えます。戻ってきた文は元に戻せます。漏れは0にならないので、後の欄を目で確かめます |
| 2:25〜2:40 | 端末で `node tools/claude-check.mjs` が、置き換え漏れの検査のあと送る中身を表示する場面 → 画面の「B. Claude で点検した結果(AI の候補)」 | 置き換えた後のファイルだけを Claude に送ります。送る中身を全部見せ、「送る」と打ったときだけ送ります。AI の候補は、法令で判定した結果とは別の欄に出します |
| 2:40〜2:50 | README の「Claude Code での作り方」と `docs/評価.md` | Claude Code が機能を1つずつ作り、固定した受け入れテスト110件と、原文との照合で確かめました。最後の判断は人がします |
