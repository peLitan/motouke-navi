# 使い方の詳細(Motouke Navi)

README.md から移した、各機能の細かい説明・限界・評価の走らせ方・出典の細部です。要点と5分で試せる手順は [README.md](../README.md) にあります。

マウスのある端末では、画面のファイルの7つの口の枠と、入口の「公告を読み込む」のタイルに、ファイルをドラッグして置いても読み込めます(1度に1つ。読み方はボタンで選んだときと同じです)。`index.html` をブラウザの窓にドラッグして開く操作とは別です。

## 受注後の段取り(着手から完成・引き渡しまで)
画面の「1.」で条件を入れて「確認する」を押し、入れた条件を行で確かめて「この内容で結果を見る」を押すと、入札前の確認と一緒に受注後の段取りの一覧が、「着手まで」「施工中」「完成・引き渡し」の段に分けて出ます。各行は、いつ・何を・誰に・状態・根拠(土木工事共通仕様書(案)令和8年3月の該当箇所の番号と原文の抜き書き)です。

もう受注していて条件を入れる前に見たいときは、入口のタイルの下の「もう受注した方は段取りの一覧へ」を押します。条件から絞らず全部の行を出し、状態はどれも「確かめる」です。一覧の上の「条件を入れる」から条件を入れて「確認する」を押すと、通常の結果に変わります。すでに「確認する」で結果を出してあれば、その結果を見せます。全部の行の件数はまとめの枠に出しません。

現場で段取りだけ見るなら、入口の「もう受注した方は段取りの一覧へ」を押します。

- 国の直轄の例です。自治体・民間は発注者の仕様書・契約書で置き換えてください
- 並べること: コリンズへの受注時の登録(1-1-1-7)、設計図書の照査(1-1-1-3)、下請負の要件(1-1-1-12)、施工体制台帳の作成と写しの提出・施工体系図の掲示と写しの提出(1-1-1-13)、施工計画書の提出(1-1-1-6)、工事着手の期日の確認(1-1-1-11)
- 施工中の段: 工事着手後直ちの工事測量(1-1-1-42)、施工途中の設計図書の照査(1-1-1-3)、工事履行報告書の提出(1-1-1-28)、事故が起きたときの連絡と工事事故報告書(1-1-1-34)
- 完成・引き渡しの段: 工事完成図(1-1-1-23)、支給品精算書(1-1-1-20)、現場発生品の引き渡しと現場発生品調書(1-1-1-21)、後片付け(1-1-1-33)、完成検査の要件の確認・工事完成通知書の提出・完成検査への臨場(1-1-1-24)、コリンズへの完成時の登録(1-1-1-7)
- 段に分けたのはこのツールの整理です。共通仕様書は段で分けていません。原文に時期の定めが無い行(工事完成図・現場発生品など)は、時期を足さずにそう書きます
- **工事目的物そのものの引き渡しは一覧に入れていません。** 引き渡しの手続は契約書(公共工事標準請負契約約款 第32条)によるもので、共通仕様書には条がありません。このツールは契約書を取得していません。「完成・引き渡し」の段の引き渡しの行は、共通仕様書 1-1-1-21 の現場発生品の引き渡しです(画面にも同じ断りを出します)
- 条件で行が変わります: 請負代金が共通仕様書の境目(500万円以上。抜き書きから読む)未満ならコリンズの行を、下請けの総額が 0 なら台帳・体系図・下請負の行を、閲覧の措置を講じるなら写しの提出の行を出しません(コリンズは受注時・完成時の両方の行)。支給品精算書と現場発生品の行は、画面に入力欄が無いので、いつも「確かめる」で出します(支給材料・貸与品や、設計図書に定められた現場発生品があるかを確かめてください)。出さなかった行は「条件に合わないので出していない行」に理由つきで出ます。請負代金や下請けの有無が分からないときは、行を出して「確かめる」にします
- 発注者から直接請け負うのでなければ、行を出しません(この例は元請けの段取りです)
- 「段取りを CSV に書き出す」で、一覧をこの端末に CSV で保存できます。最後の行は「注意」で、候補であって保証や合否ではないことを書いています
- 各行の「発注者の仕様書では」の欄に、節・期限・メモを自由に書けます。ページを閉じると消えるので、残すときは印刷(PDF でも)か CSV で書き出してください。紙に出るのは「全部を印刷する」のときで、「PDF で保存・印刷」のまとめには出ません。ブラウザには保存しません。このツールは書いた内容を原文と照らしません
- 書き込みは、出し直しても、表を読み込んで切り替えても残ります。同じ id の行は国の直轄の例と読み込んだ表で同じ書き込みが出ます(和歌山県の例では施工計画書・コリンズ2行・工事着手の4行)。今の一覧に行が無い書き込みは消えませんが、今の印刷と CSV には載らないので、一覧の上に件数を出します

### 工種を選ぶ

条件の欄の「工種」で、建設業法施行令 第37条の技術検定の種目から選びます(土木(建設機械施工を含む)・建築・電気工事・管工事・電気通信工事・造園・その他)。既定は土木で、土木の出力は工種の欄を足す前と同じです(`tests/unit/work-kinds.test.mjs` で固定)。

- 建設業法施行令 第37条の技術検定の7種目のうち仕様書を読めた5種目は、土木・建築・電気工事・管工事・電気通信工事です。読んだのは各仕様書の最初の章の一部の条で、作った段取りの行は順に 21・33・38・41・21 行、すべて `node scripts/check-quotes.mjs` を通りました(2026-11-06)。残る2種目のうち、建設機械施工は専用の仕様書が無いので土木にまとめました。造園は公園緑地工事共通仕様書の表紙と目次の頁の注だけを読み、本文を読んでいないので5種目に数えていません
- 見ていない範囲: 建設業の許可の29業種のうちほかの業種の仕様書、改修の仕様書の本文(建築・電気工事・管工事で読んだのは新営の仕様書)、電気通信工事の共通費、機械の共通費のうち管工事の機械設備工事の別表に当たらないもの(建設機械施工に専用の基準など)です。共通費の別表の改修の率は仕様書の本文とは別で、Skill `estimate` の `workClass` で使えます
- 「確認する」のあと、段取りと目次の点検の見出しの下に、工種と表の出典・版・取得日が出ます。印刷・CSV にも工種が載ります(CSV は最後に工種の行を足します)
- 表の無い工種は「この工種の仕様書は見ていない」と出し、土木の表で埋めません(例外は下の造園の段取りだけ)。和歌山県の例は土木の表なので、土木のときだけ使います。読み込んだ表は工種を問わず使います
- 建築は段取りの表と、目次の点検の3つの語があります。公共建築工事標準仕様書(建築工事編)令和7年版の１章の一部の条から作った33行です。適用は新築と増築で、改修の仕様書の本文と２章以降は見ていません。積算は共通費の式だけです(「建築系の共通費」の節)
- 電気工事と管工事も段取りの表と、目次の点検の3つの語があります。電気工事は公共建築工事標準仕様書(電気設備工事編)令和7年版、管工事は同じ仕様書の機械設備工事編 令和7年版(修補版)を当て、どちらも第1編 第1章の一部の条から作りました。番号が違うので表は分けています(`data/schedule-denki.json`・`data/schedule-kan.json`)。官庁施設の営繕の基準なので、建築物の設備でない工事は発注者の仕様書で確かめてください。ほかの編と改修工事の仕様書は見ていません。目次の点検と積算は共通費の式だけです(「建築系の共通費」の節)
  - 通った行の数(`node scripts/check-quotes.mjs`。2026-11-06): 電気工事 38 行のうち 38 行、管工事 41 行のうち 41 行。照合に通らなかった行はありません
  - 建築の表にあって行にしなかった条: 1.3.2 の施工管理技術者の証明の資料と、1.3.4 の工事用電力設備の保安責任者。電気設備工事編・機械設備工事編の第1章に同じ語の条が無いためです。代わりに 1.3.2 の電気保安技術者の行を置きました
  - 足した行: 概成工期の明記(1.2.1(6))、総合試運転調整の計画書・立会い・報告書、施工の立会い、試験成績書の提出。管工事はさらに、技能士の証明の資料(1.5.2(3))と標識の設置(1.7.4(1))。電気保安技術者・概成工期・技能士は適用の条件に入力の欄が無いので、「確かめる」の行にします
- 電気通信工事は段取りの表だけあります。電気通信設備工事共通仕様書 令和8年版(表紙の版の書き方)の第1編 第1章の一部の条から作った21行です。節の番号と条の型が土木工事共通仕様書と同じなので、土木の表と同じ行の型にしました(`data/schedule-tsushin.json`)。適用は土木工事に係る電気通信設備工事(1-1-1-1 の1)で、第1編 第2章と第2編以降は見ていません。目次の点検の表は作っていないので「見ていない」と出します。共通費も見ていません
  - 通った行の数(`node scripts/check-quotes.mjs`。2026-11-06): 21 行のうち 21 行。照合に通らなかった行はありません
  - 土木の表と違うところ: 施工体系図の写しの文に「情報通信技術で確認できる措置を講じている場合を除き」が無いので、写しの行は措置があっても出します。台帳の写しの文にはあるので、措置があれば出しません。支給品精算書の文に港湾工事・空港工事の書き分けはありません。工事測量と事故報告書は抜き書きを1文にしたので、残りの決まりは注意の欄に書きました
- 造園は段取りだけ土木の表を当てます。公園緑地工事共通仕様書(令和6年5月)の目次の章は基盤整備から自然育成までの6つで総則が無く、注1 に「国土交通省 土木工事共通仕様書 令和6年度版」を本文で引用するときの書き方があるためです。注2 の用語の定義は「令和4度版」と書いてあります(原文の字のまま)
  - 土木の表を当てたのはこの道具の整理です。公園緑地工事共通仕様書に「総則を適用する」という文があるわけではありません
  - 版が違います。土木の表は令和8年3月の版で、引用は令和6年度版です。令和6年度版は取り込んでいないので、版の違いが行に当たるかは確かめていません。このことと出典を、段取りの出典の行と CSV の工種の行に必ず出します
  - 見ていないもの: 公園緑地工事共通仕様書の本文、造園の目次の点検、造園の積算(Skill `estimate` は額を出しません)
- 法令の判定・安全の法令の候補・公告の読みは工種を問わず出します。「工事の種類」(建築一式かそれ以外か)は建設業法の金額の境目を決める欄で、工種とは別です
- Skill `estimate` は `conditions.workKind` で工種を受け取ります。土木は積算の表で、建築・電気工事・管工事は共通費の式で額を出します。どちらも無い工種は額を出しません

### 例を切り替える
段取りの見出しの下のボタンで、「国の直轄の例(国が発注する工事)」と「和歌山県の例(7つの節だけ)」を切り替えます。自分の発注者の表は、下の折りたたみ「直轄とは・例の違い・自分の表を読み込む」から読み込みます(3つ目の選び方)。読み込むと2つのボタンは押されていない形になり、「読み込んだ表を使っています」と「国の直轄の例に戻す」が出ます。

- 和歌山県の例は `data/specs/wakayama_r0711_rows.json` を index.html に組み込んだものです。ファイルの読み込みと同じ確かめを通り、外へは送りません
- 和歌山県「土木請負工事必携(令和7年11月)」の 1-1-1-6〜12 の7つの節だけです。行は 31(段取り 15・記載項目 16)で、1-1-1-11 から作った行はありません。条件は当てはめないので、要らない行も出ます
- 切り替えると、施工計画書の目次の点検の記載項目も同じ例に変わります
- 和歌山県の例を選ぶと、加工して作成したこと・和歌山県が作成したものではないこと・出典と取得日を注記に出します。同じ表示は画面の一番下の「使った資料の表示」にいつも出ます
- 読み込んだ表を使っているときに和歌山県の例へ移ると、読み込んだ表は手放します。もう一度使うときはファイルを選び直してください

### 発注者の仕様書の表を読み込む
「自分の発注者の表を読み込む」で、Skill `spec-to-rules` の `check-rows.mjs --out` が書いた行のファイル(見本: `data/specs/wakayama_r0711_rows.json`)を選ぶと、国の直轄の例の代わりに、その行で段取りと施工計画書の記載項目を出します。「国の直轄の例に戻す」で戻せます。

- ファイルは画面の中で読むだけです。外へ送らず、ブラウザにも保存しません(ページを閉じると消えます)
- ファイルの形: `{ "source": { "publisher": 発注者, "document": 書類の題名(省略できる), "title": 題名, "edition": 版, "url": URL, "fetchedAt": 取得日 }, "rows": [ ... ] }`。発注者・題名・版が無いファイル、壊れたファイル、行の形が違うファイル、1MB を超えるファイルは、理由を出して拒み、今の表のままにします
- 画面に、加工して作成したことと、出力が発注者の作成したものではないことを、出典の値から組み立てて出します。書類の題名は `document` を使い、無ければ `title` を使います。見本のファイルでは「和歌山県「土木請負工事必携(令和7年11月)」を加工して作成」「この出力は和歌山県が作成したものではありません」と出ます。この表示は段取りと施工計画書の目次の点検の注記に出て、印刷にも入ります。CSV には入りません
- 画面に、読み込んだ行の数と出典を出します。画面は原文を持たないので、原文とは照らしません。手で書いたファイルでも形が合えば読めるので、画面の注記は「照合済み」とは書かず「画面では原文と照らしていません」とだけ出します
- 行には条件の欄が無いので、入力の条件を当てはめません。どの行も状態は「確かめる」で、金額や下請の有無で要らない行も出ます。「判断できない」の欄は理由を添えて出します
- 段を決められない行は「判断できない」の段にまとめます
- 読み込んだ記載項目には言い換えの語が無いので、書き方が違う見出しは抜けの候補に出ます
- 段取りか記載項目の片方の行しか無いファイルでは、無い側は国の直轄の例のままです
- 共通仕様書に期限が書かれていない行(台帳・体系図など)は、期限を足さずに「原文に期限は無い」と出します。期日・相手・出し方の細かいところは、特記仕様書・契約書と監督職員の指示で確かめてください

## 施工体制台帳の点検
画面の「3-1. 施工体制台帳の点検」に、施工体制台帳を見出しと「| 項目 | 内容 |」の表の形で貼って「台帳を点検する」を押すと、抜け・食い違いの候補を根拠の条つきで出します(書き方は画面の「台帳の書き方」を開くと見られます)。

- 点検すること: 下請けの商号又は名称・工事の内容・工期の空(建設業法 第24条の8第1項)、元請け・下請けの技術者の氏名・資格の空(第26条第1項)、下請けの総額が施行令 第2条の金額以上なのに元請けが監理技術者でない(第26条第2項)・特定建設業でない(第3条第1項第2号)、技術者が「非専任」なのに専任が要る工事(第26条第3項・施行令 第27条第1項)
- 技術者の専任: 台帳の「専任・非専任」の欄に「非専任」と書いた技術者だけを点検します(欄が無い・空なら点検しません)。工事一件の請負代金の額(元請けは発注者との契約の額、下請けはその下請契約の額)が施行令 第27条第1項の金額(抜き書きから読む。それ以外の工事 4,500万円、建築一式 9,000万円)以上で、発注者が「公共」なら候補にします。境目を決める工事の種類は、元請けは画面の「工事の種類」、下請けはその下請工事です(第27条第1項の「当該建設工事」)。下請けの工事の種類は台帳の「工事内容」に「建築一式」と書いていなければ建築一式でない(4,500万円)として比べ、4,500万円以上 9,000万円未満のときは「この下請工事が建築一式なら専任は要らない」を「確かめること」に付けます。入札前の確認で下請けとして使うときも、「工事の種類」には自分が請け負う下請工事の種類を選びます。「公共」は第1号(国又は地方公共団体が注文者)に当たるものとして読みます。民間の工事は施設・工作物の種類(第2号・第3号)で決まるので「判断できない」に出します。第26条第3項ただし書(第1号: 政令で定める金額未満で移動時間・情報通信技術の措置などの要件を満たす場合。この金額の原文は取り込んでいません。第2号: 監理技術者を補佐する者を専任で置く場合)は台帳から決められないので、候補に「確かめること」として付けます
- 発注者(公共・民間)と工事の種類(建築一式かそれ以外か)は、上の「1.」の選ぶ欄の値を使います。元請けの許可の種類は台帳の許可番号の「(特-06)」「(般-06)」から読み、読めなければ上の欄の値を使います
- 下請けの額が分からないなど、決められないことは「判断できない」に出し、推測で候補にしません。読めなかった行・金額・日付は「台帳の文を読んだときの注意」に出します(金額は「万」を使わず数字で書いてください)
- 「点検の結果を CSV に書き出す」で、候補と判断できないことを根拠の条つきで CSV に出せます(この端末に保存するだけです)
- 候補は指摘の候補で、合否ではありません。第26条第4項(現場の数)・施行令 第27条第2項(密接な関係のある工事)は見ていません

  - 「工事の種類」が建築一式工事でも、工種が建築・電気工事・管工事ならこの3つの語で比べます(工種が土木のままなら、これまでどおり「判断できない」と出します)

## 金額の書き方(画面の欄と Skill `bid-intake`)
画面の「請負代金の見込み」「下請けの総額」の欄は、数字だけの額のほかに、億・万・千円・百万円の単位を付けた額を読みます。単位を付けたときは、欄を離れると欄の下に「134,200,000円 として読みました」のように円にした値を出します。千円の額を円の欄にそのまま入れると額が1000倍ずれ、金額の境目の判定がまとめて裏返るので、出た値を見て桁を確かめてください。数字だけで入れた額には、この行を出しません(「134,200円」は 134,200円 として読み、千円の書き落としと見て読み替えることはしません)。

Skill `bid-intake` は公告の文の中から額を探すので、読み方が画面の欄と少し違います。下の表は 2026-11-07 に両方の部品で測った結果です(値は架空)。

| 書き方 | 画面の欄 | `bid-intake`(`check-conditions.mjs` の額の読み) |
|---|---|---|
| 134,200,000円・134200000 | 読む(円は無くてもよい) | 円の付いた形だけ読む |
| 1億3,420万円・全角の １億３，４２０万円 | 読む | 読む |
| 134,200千円 | 読む | 読む |
| 134,200 千円(千円の前に空白) | 読む(空白は除く) | 読まない |
| 134.2百万円 | 読む | 読まない |
| 1.5億円・12.5万円(小数) | 円にして端数が出ないときだけ読む | 読む(端数は四捨五入) |
| 5千万円・一億円(漢数字の位) | 読まない。「5,000万円」と書く | 読む |
| 1億・5千万(円が無い) | 読まない | 読まない |
| 約1億円・-1億円 | 読まない | 「約」「-」を見ずに 1億円 と読む |

- 画面の欄は、単位を使うときに末尾の「円」が要ります。億と万は「1億3,420万5,000円」のように続けて書けます。千円と百万円は、その前に数字だけを書く形(「134,200千円」)で読みます
- 画面の欄が読めない値は、欄を離れたときに欄の下に理由を出し、判定に使いません。端数が出る小数(例 1.23456万円)と大きすぎる額は、それぞれの理由を出します

## 公告から条件を拾う(Skill `bid-intake`)
入札する工事の公告・入札説明書・仕様書の文を Claude Code に渡すと、Skill `bid-intake` が画面と判定が使う条件を拾います。手順は `plugin/skills/bid-intake/SKILL.md` です。

- 拾う欄は 15 です(発注者、工事名、工事場所、工期、入札の日時、予定価格、最低制限価格・調査基準価格、工事の種類、工事の内容、等級、求める建設業の許可、地域の要件、施工実績、技術者の要件、下請けの扱い)
- `check-conditions.mjs` は AI を使わずに照らします。抜き書きが原文に無い値と、値が抜き書きに無い値は外します。外した欄は「公告に書いていない」にせず「確かめが要る」にします
- 食い違いは、外さずに「確かめが要る」にして理由を付けます。見るものは `SKILL.md` の「機械が見ること」に並べています。100万円より小さい額を疑うのは、単位の落ちを探すための目安で、法令の境目ではありません
- 状態が「公告に書いていない」になるのは、欄の語が原文に1つも無いときだけです。語の一覧に無い言い方で書いてあれば、書いてあっても見つかりません
- Claude が気づいたことは、機械の結果と別の節に出します

画面では、入口のタイル「公告を読み込む」か、段1 の折りたたみ「公告から拾った条件を読み込む」で `--out` のファイルを開きます。

- 入るのは、発注者(公共・民間)、工事の種類、請負代金の見込みの3欄だけです。状態が「拾えた」の値だけを入れます
- 請負代金の見込みに入れるのは、税込みと書いてある予定価格だけです。予定価格は上限の見込みで、請負代金そのものではありません。税抜きの額は税を足さずに入れず、理由を出します
- 公共か民間か、建築一式かそれ以外かは Claude の分類です。機械は「建築一式」の語と分類が合うことだけを確かめ、公共か民間かは確かめません
- 元請けか下請けか、下請けの総額、許可の種類、技術者の資格は「公告からは分からない」と出して、入れません。安全の法令の問いにも入れません(工事の内容は表で読めます)
- ファイルはブラウザに保存しません。壊れたファイルは拒み、入力欄を変えません

同じタイルと枠に、文字の入った公告の PDF を置くこともできます(選ぶときは .pdf を選びます)。画面ができるのは、PDF の文字を読んで段1 の「公告の参加の条件」の欄に入れることだけです。

- 読んだ文字は空白と折り返しを整えて欄に入れます。頁の間の「―― 2頁 ――」の行は残します。頁をまたいだ文は、元請けの実績を見るときにはつなげて見ます
- 見るのは元請けの実績を求める文があるかだけです。金額・工事の種類・等級・地域などの条件は拾いません。発注者や請負代金の欄は変えません。拾うのは Skill `bid-intake` で、渡すのは文のファイルです。欄の文をメモ帳に貼り、.txt で保存して渡してください
- 当たれば、結果の「確認が要る点」に抜き書きを出します。当たらないときも「無い」とは言わず、公告の本文で確かめるよう知らせます。語を見ているだけなので、表の PDF で「。」の無い長い並びになると、公告の条件でない文に当たることがあります
- 欄に文があるときは入れません。欄を空にしてから置き直してください。読んでいる間に欄へ書いた文も消しません
- 読めない PDF(紙を写した画像だけ・保護つきなど)は、理由と次の手を出して欄を変えません。一部の頁が読めないときは、頁の番号を読み込みの枠の下に出します
- 入力の確かめの画面には、欄の文の頭の 200 字だけを出します。全文は「変更」で欄を見てください
- ほかの口(自分の発注者の表・辞書など)は PDF を読みません

段1 の「公告の参加の条件」の欄には、公告の施工実績の文を手で貼ることもできます。元請けとしての実績を求める文があれば、結果の「確認が要る点」に「参加できない場合があります」の形で、その文を付けて出します。「元請け、下請けを問わず」の文、「元請又は一次下請」の文、次の文の「ただし」で下請けの実績も認める文、技術者への条件の文(最初の読点までに技術者が主語か見出しとして来る文、「…を有する監理技術者を配置する」の形の文。会社の語と技術者を並べた文と、読点の無い文で実績の条件が先に来た文は除きます)と、実績の条件が無いときは出しません。参加できるかどうかは判定しません。別の公告のファイルを読み込むと、この欄の文は置き換わります。読み込むときは、PDF から写したときの連続した空白と文の途中の改行を詰めて入れます(語は変えません。条件のファイルの抜き書きは原文のままです)。手で貼った文は詰めません。

元請けで下請けがあるとき、下請けの総額が請負代金の見込みより大きければ、結果の「確認が要る点」に桁か欄の確かめを出します。判定の項目は変えません。

入札前の確認の結果には、「労務費と処遇の候補(確認が要る点の数に入れません)」の節が出ます。建設業法 第20条第6項(見積書の材料費等を、通常必要と認められる額を著しく下回るように変えるよう求めることの禁止)と第25条の27第2項(自社の労働者の処遇を確保する努力)を、抜き書きつきで出します。元請けで下請けに出す場合のほか、下請けでもさらに下請けに出す場合に第20条第6項を出します。下請けに出さないと入れたら第20条第6項は出しません。第25条の27第2項は元請け・下請けを問わず出します。当たる・当たらないは判定せず、「確認が要る点」の件数にも数えません。

見本は `docs/samples/bid-intake/` にあります(架空の公告と説明書、拾った条件、結果の表 `拾った結果.md`、画面用のファイル)。工期と予定価格を2つのファイルでわざと違えてあります。拾った条件は、作者の側の Claude が `SKILL.md` の手順に沿って書いたもので、新しい会話で Skill を起動して作ったものではありません。

測ったこと: 架空の公告5件(作る側が書いたもの)と、実在の公開の公告2件で、拾いの正しさを測りました(`docs/評価.md` の8)。公開の公告を文にした作業のファイルと正解の表はリポジトリに入れていません。そのため、`scripts/measure-bid-intake.mjs` に `--answers` と `--notices` でフォルダを渡して測ります。台本は、1つの欄で拾った全部の行で判定する数と、欄の最初の1行だけで判定する数を並べて出します。全部の行の数え方は、余分な行や誤った行を数に出しません。

分かっている弱い所: 実在の公告では2件の30欄のうち1欄が外れました(全部の行の数え方。最初の1行の数え方では3欄)。元請けの施工実績の条件は、拾った表では状態が「拾えた」のままです。画面に読み込むと、施工実績の抜き書きが「公告の参加の条件」の欄に入り、元請けとしての実績を求める文なら結果の「確認が要る点」に出ます。語で見るだけなので、言い回しによっては漏れ、取り違えることもあります。PDF から文にすると、文の途中に空行が入ったり、表の見出しと値の行がずれたり、語の途中に欄の名前が挟まったりすることがあり、機械はこの崩れを見ません。数字と億・万・円の間の半角・全角の空白は、同じ行の中なら額として読みます(2026-11-06 に直しました)。「123,400 千円」のように数字と「千円」の間に空白がある形は額として読まず、正しい値でも外します。

確かめていないこと: 実在の公告は2件・各1回だけで、率は言えません。ページをまたぐ文での動きは試していません。公告の語を別の欄に読み替えた値(「見積の上限額」を予定価格にするなど)は、額の形に問題がなければ機械は「拾えた」のままにします。1枚の中で複数の工事を並べた公告は扱いません。

## 労働安全衛生法の候補
段2 の「受注後の段取り」の下に「安全の法令の候補」の欄があります。元請けに掛かりそうな労働安全衛生法の義務を、原文の抜き書きつきの候補として出します(部品は `src/safety.mjs` の `safetyCandidates`、規則表 `data/safety.json`、画面は `src/ui/safety-view.mjs`)。注記は折りたたみの外に出し、候補と問いは折りたたみ「労働安全衛生法で、元請けに掛かりそうなもの(n件)」の中にあります。「確認する」を押さなくても、問いの欄を変えるとすぐ描き直します。入れた答えは保存しません。

問いは4つです(3 には橋の続きがあります)。

1. 仕事の一部を他社(個人を含む)に請け負わせるか。段1 の下請けの総額の答えを見せ、自分で選ぶまでは段1 の答えに合わせます(空と「分からない」は「まだ分からない」)
2. 同じ場所で働く人の数。自社・下請け・一人親方などを含め、原文の境目から作った範囲で選びます。下請けを使わないときは出しません。「常時」の意味は条文に無いので説明を出しません
3. 工事の中に次のものがあるか。令 第7条と則 第90条の項目は条件が違うので分けています。ずい道は内部に人が立ち入る項目と立ち入らない項目があり、橋は支間と場所を別に聞きます
4. 行う作業。地山の掘削・土止め支保工・型枠支保工・足場・金属製の建築物の骨組み・塔・木造建築物の構造部材の組立て等・コンクリート造の工作物の解体・破壊・酸素欠乏危険場所・石綿等の取扱いの9つと、「どれも行わない」「まだ分からない」です。作業で選ぶので、工種を変えても問いは変わりません

| 候補 | 読む入力 | 根拠 |
|---|---|---|
| 元方事業者の措置・特定元方事業者の措置 | 下請けを使うか | 法 第15条・第29条・第29条の2・第30条(第4項の指名を含む)、則 第634条の2 |
| 統括安全衛生責任者の選任と、対で元方安全衛生管理者の選任 | 下請けを使うか・同じ場所で働く人の数・工事の中身 | 法 第15条(第3項の指名を含む)・第15条の2、令 第7条 |
| 工事の計画の届出 | 工事の中身(規模の数があれば数で決める) | 法 第88条第2項・第3項・第5項、則 第18条の2の2・第89条・第90条 |
| 作業主任者の選任 | 行う作業 | 法 第14条、令 第6条 |
| 安全衛生責任者の選任(下請けのとき) | 同じ場所で働く人の数・工事の中身 | 法 第16条 |

- 人数・高さ・支間・届出の日数は、規則表に書かず、抜き書きの漢数字から読みます。抜き書きは `node scripts/check-quotes.mjs` で原文と照らします
- 結論は「要る」「未回答」「確認が要る」の3つで、「要らない」の札は出しません。当てはまらないものは候補に出しません。何も当たらなければ「選んだ作業では、この一覧の条件には当たりませんでした」と出します。未回答と確認が要るの候補には、何を入れれば決められるかを欄へのリンクで付けます
- 計画の届出は、則 第89条の仕事に当たれば厚生労働大臣へ、第90条の仕事に当たれば労働基準監督署長へ分けます。第89条の仕事は第90条の候補に重ねて出しません
- 段1 で「下請け」を選ぶと、元請けだけに掛かるもの(元方事業者の措置・統括安全衛生責任者・法 第88条第2〜4項の届出)を出さず、下請けにも掛かるもの(安全衛生責任者・作業主任者)を出します。安全衛生責任者は、元請けが統括安全衛生責任者を選任すべき現場かどうかで決まるので、人数と工事の中身から同じ境目で読みます
- 結果の先頭の数字のカードと、まとめには、今の件数と別に「安全の法令の候補」が出ます。「全部を印刷する」の紙と CSV(「結果を CSV に書き出す」)には候補と入れた条件が、「PDF で保存・印刷」のまとめには件数と入れた条件が載ります。問いの欄そのものは紙に出しません。この CSV の「注意」の行は入札前の確認と台帳の行の終わりにあり、そのあとに工種と安全の法令の候補の行が続きます
- 見本には地山の掘削と土止め支保工を入れてあります

限界:

- 画面の見え方は、ブラウザで確かめていません。単体の試験は描いた HTML と作り物の DOM での動きを見ています。実際の使いやすさは測っていません
- 見た条文は 2026年10月1日施行の改正までです。2027年1月1日・4月1日施行の未施行の改正は入っていません
- 見ていない条があります。店社安全衛生管理者・救護の措置・注文者の措置の条、第30条の措置の細目(協議組織の開き方や巡視の回数など)は取り込んでいません

- 作業主任者は上の9つの作業(令 第6条 第9号・第10号・第14号・第15号・第15号の2・第15号の4・第15号の5・第21号・第23号。第9号と並べて第11号も根拠に出します)だけです。ほかの号(ずい道の掘削、橋梁の架設、高圧室内作業など)は判定しません
- 酸素欠乏危険場所の一覧(令 別表第六)は取り込んでいません。候補に、原文で確かめるよう添えます
- 「軒の高さ」の決まり(建築基準法施行令)は取り込んでいません。候補に、原文で確かめるよう添えます
- 石綿の号は全文を問いに出します。後半が引く令 第16条は取り込んでいません
- 人数は範囲で選ぶので、「常時」に当たるかの判断は人がします
- 号の括弧書きの除外(掘削面の下方に労働者が立ち入らない機械掘削、ゴンドラのつり足場など)は、問いの言葉に原文のまま入れ、候補にも添えます。読んで確かめてください
- 第30条の指名(発注者が仕事を分けたとき)と、仕事を自ら行う発注者がいるときは判定しません。掛かる先が変わることを注記で添えます。第15条第4項(救護の技術的事項の管理)は判定しません
- 則 第90条の「建設等」は改造・解体を含みますが、令 第7条の言葉は「建設の仕事」です。ずい道の改造・解体に低い方の人数の境目が掛かるかは原文から判断できないので、ずい道の項目を選べば低い方の境目を使います

## 参考の積算額の計算(`src/estimate/`)
数量と施工パッケージの対応を渡すと、直接工事費から工事価格(税抜き)までをプログラムで計算します。AI は使いません。数量の表から使うときは次の節の Skill `estimate` を使います。画面にはつないでいません。数量の表からパッケージに当てる所は、次の作業で足します。

### 使うデータを手元に取る
```
node scripts/fetch-estimate-data.mjs
```
国土交通省のサイトから3つの PDF を取り、表の形にして `tmp/estimate-data/` に置きます(git の対象の外)。標準単価表は利用条件を確かめていないので、リポジトリに写しません。2026-11-05 の実行では、施工パッケージ 411 件・行 9,177 件・読めなかった行 0 件・構成比の計が 100 から 0.5 ポイント以上外れた行 0 件でした。411 件のうち 100 件は「物価資料等による」の材料費で、表がありません。先に取った PDF を使うときは `--pdf-dir DIR`、置き場を変えるときは `--out DIR` です。

標準単価表は国土技術政策総合研究所の Excel ではなく、国土交通省の通知の別添の PDF を読みます。中身は同じ通知の標準単価表ですが、Excel と1行ずつ比べてはいません。PDF の形が変わると読めない行が増えるので、実行のあとの数を見てください。

### 計算の順
| 段 | 中身 | 根拠 |
|---|---|---|
| 積算単価 | 標準単価 × 機労材構成比の補正式。有効数字4桁、5桁目以降切り上げ | 標準単価表 Ⅱ-1(PDF p.5・p.6) |
| 直接工事費 | 数量 × 積算単価。1円未満を切り捨てて積む | 運用(PDF p.9) |
| 共通仮設費 | 対象額 × 共通仮設費率 + 積上げ額。率の分は 1,000円未満を切り捨て | 運用 別表第1(PDF p.19・p.20) |
| 現場管理費 | 対象純工事費 ×(現場管理費率 × 補正係数 + 補正値)。1,000円未満を切り捨て | 運用 別表第2(PDF p.43・p.44) |
| 工事価格 | 工事原価 + 一般管理費等。10,000円単位にして、調整は一般管理費等で行う | 運用 別表第3〜第5(PDF p.47) |

結果には1行ごとに施工パッケージの番号・条件・頁を付けます。率は段ごとに表と頁を返します。

### 人が入れるもの
- 機械・材料・市場単価の補正: 東京・基準年月と積算地区・積算年月の単価を、行の `manual` に入れます。入れるまでは `humanFields` に空の欄として残り、比 1 のまま計算します。補正していない部分の額と割合を `uncorrectedAmount`・`uncorrectedPercent` で返します
- 労務単価に無い職種も同じ空の欄に出ます
- 共通仮設費・現場管理費の地域の補正係数、現場管理費の補正値(最高 2%)、積上げ額、前払金支出割合、契約保証の区分。入れない場合の扱いは `assumptions` に書いて返します
- 直接工事費を人が入れて、間接費だけを出すこともできます(`estimate({ directCost, kind })`)

### 確かめたことと限界
- 補正式は、標準単価表の通知の計算例3つ(①②③)と、示された桁まで一致しました。運用の PDF に間接費の通しの計算例は無いので、率は46行すべてを抜き書きと機械で照らし、式の端の値が別表の固定の率と 0.1 ポイント以内で合うことを確かめました。額は手で計算した値と比べています
- 九州地方整備局の公表の積算内訳6件と比べました([評価.md](評価.md) の9節)。公表の直接工事費を入れると、共通仮設費と現場管理費は1件で同じ額になり、5件は 9〜30% 低く出ました。地域の補正係数を入れていないためと見ていますが、確かめていません。一般管理費等は、5件で率の差がちょうど 0.04 でした(契約保証の補正を入れていない場合の値と同じです)
- 施工パッケージに無い工種(歩掛で積むもの、市場単価のもの)は合計に入らず、`excluded` に理由つきで出ます。その分の間接費も入りません
- 処分費等が対象額の 3% か 3千万円を超えるときの調整は入れていません。知らせだけを出します。間接費は大きめに出ます
- 標準単価表 Ⅱ の②〜⑥の補正のうち、実数入力・時間外割増・豪雪補正・支給品・無償貸付の計算は入れていません。代表規格の単価を差し替える形なら `manual` で入れられます
- 一覧の ※1・※2 のパッケージには、熊本県・石川県で別の単価表を使うものがあります。別の表は取っていません
- 代表労務の名前に付く「*」の意味は通知の見方に書いてありません。同じ職種の労務単価で補正しています
- 出す額は参考です。発注者の積算と同じ額にはなりません。会社の原価(自社の人件費・下請けの見積もり)は含みません

## 建築系の共通費(`src/estimate/kyotsuhi.mjs`)
建築・電気工事・管工事は、公共建築工事共通費積算基準(令和8年改定)の別表の式で、人が入れた直接工事費から工事価格(税抜き)までを計算します。土木の `src/estimate/indirect.mjs` は別の基準で、計算は変えていません。AI は使いません。

Skill `estimate` の `conditions` に次を書きます。画面には欄がありません(積算は画面につないでいないため)。

| キー | 中身 |
|---|---|
| `workKind` | `kenchiku`(建築工事)・`denki`(電気設備工事)・`kan`(機械設備工事) |
| `directCost` | 直接工事費(円)。必須 |
| `months` | 工期(か月)。必須 |
| `workClass` | `shinei`(新営。既定)か `kaishu`(改修) |
| `disposal` | 処分費(円)。直接工事費に含めたうえで、率の計算からだけ除く |
| `stacked` | 共通仮設費率に含まれない内容の積み上げ額(円) |

| 段 | 式 | 出どころ |
|---|---|---|
| 共通仮設費 | (直接工事費 − 処分費)× Kr + 積み上げ額 | 別表－1〜6 |
| 現場管理費 | (純工事費 − 処分費)× Jo | 別表－8〜13 |
| 一般管理費等 | 工事原価 × Gp | 別表－15 |

- 係数は手で書いていません。`node scripts/fetch-kyotsuhi.mjs` が PDF を文にして `data/sources/mlit-kyotsuhi-r8.txt` に置き、別表の式・係数・範囲を読んで `data/kyotsuhi-rates.json` に書きます。`node scripts/check-quotes.mjs` が原文から読み直して全部同じかを見ます
- 率の範囲(別表の 注３)の外は「別途」と出し、その先の段も額も出しません。一般管理費等率は範囲の外も両端の率が決まっているので「別途」になりません
- 率は別表の 注４ のとおり小数第3位を四捨五入します。金額の端数の処理は基準に定めが無いので、1円未満だけ切り捨てます
- 施工パッケージの標準単価表は土木の表なので、建築系では `lines` を積みません。渡すと「合計に入っていない行」に出ます
- 基準に定義の文が無く、この道具の読みで決めたこと: 純工事費は直接工事費+共通仮設費、工事原価は純工事費+現場管理費。処分費は直接工事費に含まれているものとし、率を掛ける額からも除く。電気工事は電気設備工事、管工事は機械設備工事に当てる。共通仮設費か現場管理費が「別途」のとき、その先の段を出さないのも道具の決め方です(注３が別途にできるとするのはその費目だけです)
- 契約保証費は入れていません。共通仮設費の全額を積み上げる場合と、設計変更の計算(基準の 2(5)・3(5)・4(4))には対応していません
- 工種は1つです。建築と設備を一緒に発注する工事を1つの率では計算しません
- 昇降機設備工事の別表(－7・－14)は読みましたが、工種に当たらないので使っていません
- 公表の額と比べた測りはしていません。官庁施設の営繕の基準で、発注者によっては別の基準を使います
- 出す額は参考です。発注者の積算と同じ額にはなりません。会社の原価(自社の人件費・下請けの見積もり)は含みません

## 数量の表から参考の額を出す(Skill `estimate`)
金抜き設計書や数量総括表の文を Claude Code に渡すと、Skill `estimate` が行を施工パッケージに当て、参考の額を出します。手順は `plugin/skills/estimate/SKILL.md` にあります。表は先に手元へ取っておきます(上の「使うデータを手元に取る」。plugin の写しは `plugin/skills/estimate/scripts/fetch-estimate-data.mjs`)。

| 係 | すること |
|---|---|
| Claude | `find-packages.mjs` で表を探し、行ごとに、数量の表の抜き書き(`quote`)と標準単価表の行の文(`tableQuote`)と理由を書く。迷う行、施工パッケージに無い行は `match: null` にする |
| `check-estimate.mjs`(AI を使わない) | 抜き書きと単位を照らす。合わない行は合計に入れない。通った行を `src/estimate/` の写しで計算する |
| 人 | 工種区分、当て方、空の補正の欄、合計に入っていない行を確かめる |

```
node plugin/skills/estimate/scripts/check-estimate.mjs tmp/当てた結果.json 数量総括表.md --md tmp/参考の額.md --out tmp/参考の額.json
```
`--tables DIR` で表の置き場を変えられます(既定は `tmp/estimate-data`)。機械が入れなかった行があると終了コードは 1 です。

合計に入れない行: 数量の表に抜き書きが無い、名前・数量・単位が抜き書きに無い、抜き書きが2行以上、標準単価表に番号が無い、`tableQuote` がその番号の行の文と全部同じでない、数量の表と標準単価表の単位が違う(km と m も換算しません)、標準単価が無い。

確かめが要る(合計には入れる): 同じ抜き書きを2度使った行、行の名前と当てたパッケージで漢字が1字も重ならない行。数字があるのにどの抜き書きにも入っていない文の行も数えます(題名の年なども混じります)。

見本は `docs/samples/estimate/` にあります(架空の数量の表、架空の標準単価表と労務単価、当てた結果、結果の文書 `結果.md`)。標準単価表は利用条件を確かめていないので、見本の表は実物の写しではなく、値も架空です。見本の額に意味はありません。

確かめたことと限界:
- 確かめたのは照合と出力の動きです(単体の試験 `tests/unit/estimate-skill.test.mjs`)。Claude の当て方の正しさは測っていません
- 公表の積算内訳3件の数量で動かすと、公表の文だけで行が決まるものに絞ったため、公表の直接工事費の 0.5〜4.7% しか積めませんでした。比べられた 13 種別(盛土・法面整形・掘削・不陸整正)はすべて公表より低く、-11.4%〜-0.5% でした([評価.md](評価.md) の9節)。ほかの工種のずれは分かりません
- 舗装などの「実数入力」の行は、厚さによる計算を道具が持っていません。当てると表の額のまま積みます
- 実物の標準単価表と労務単価で動かしたのは、架空の数量の表の2行(うち1行は当てない行)で1回だけです
- 機械は文字と単位だけを見ます。条件の欄の数字(「5,000m3未満」など)と数量の大小は見ません。条件の欄は PDF の列の境目を持たず、空白でつないだ文です。数量と同じ数字が別の欄(行の番号、厚さなど)にあると、列の取り違えを見分けられません
- 合計に入っていない行は単価が決まらないので額を出せません。割合は行の数で、額の割合ではありません
- 補正していない部分は、機械・材料・市場単価のほか、基準の表に無い職種の労務も含みます
- 工種区分は人が確かめます。地域の補正係数などは、入れなければ前提の節に書いて計算します
- 出す額は参考です。発注者の積算と同じ額にはなりません。会社の原価(自社の人件費・下請けの見積もり)は含みません

## 文の置き換え(外のサービスに貼る前に)
画面の「A. 文の置き換え」(閉じた折りたたみ「ここからは別の道具」を開いた中)で、貼り付けた文の人名・会社名・現場名・住所・電話・メール・許可番号を、〔人名1〕〔会社名1〕のような記号に置き換えます。

1. 人名や現場名など、形からは見分けられない語は「辞書に足す」で種類を選んで足す(例 架空の人名「甲野 一郎」を人名として)。1字の語(例「林」)も足せますが、ほかの語の一部(「小林」など)も置き換わるので、足したときに注意を出します。足した語が会社名・メール・住所・電話の形の長い語の中に収まるときは、長い方をまとめて置き換えます(「林」を足しても「小林商事株式会社」は会社名1つになり、途中に記号は入りません)。英数字の語は英数字の途中には当てません(「a」が「data」に当たらない) 足した語が、敬称・役職・欄名から見つけた長い名前の中にあれば長い方を置き換えます(「林」を足しても「担当者: 小林 一郎」は全部が〔人名1〕)。まわりに手がかりが無い所では、足した語の所だけが置き換わります
2. 文を貼り付けて「置き換える」を押すと、前・後・対応表が並びます。同じ語はいつも同じ記号になります(空白の有無だけの違いも同じ記号)
3. 金額は「そのまま」か「境目以上・未満の形」かを選べます。境目の形にした金額は、戻しても元の金額には戻りません
4. 後の欄の文を外の AI などに貼り、戻ってきた文を「元に戻す」に貼ると、記号を元の語に戻します
5. 対応表と足した語はこの画面のメモリの中だけに持ちます。ページを閉じるか「対応表と足した語を消す」を押すと消えます
6. あとで戻したいときは「対応表を書き出す」で対応表(足した語を含む)を JSON のファイルとしてこの端末に保存し、次に開いたときに「対応表を読み込む」でそのファイルを選ぶと、「元に戻す」で使えます。読み込んだあとも、同じ語は同じ記号のままです。今の対応表は読み込んだものに置き換わります。壊れたファイルや別のファイルは読み込まず、理由を出します(今の対応表はそのまま)
7. 「辞書に足す」で足した語は、ページを閉じると消えます(ブラウザには保存しません)。次も使いたいときは「辞書を書き出す」で、足した語と種類だけを JSON のファイルとしてこの端末に保存し、次に開いたときに「辞書を読み込む」でそのファイルを選びます。書き出すときに「このファイルには元の名前が入っている」と画面に出し、確かめてから保存します。辞書のファイルには記号・対応表は入りません(戻すための対応表は 6 の「対応表を書き出す」)
8. 辞書を読み込むと、今の足した語に加えます(同じ語は読み込んだ種類にします)。対応表は変えません。壊れたファイル・形の違うファイル(JSON でない・このツールで書き出した辞書でない・版が違う・語や種類が無い・画面に無い種類・同じ語が違う種類で重なる・長すぎる語や改行の入った語・1MB を超える)は読み込まず、理由を出します(今の辞書はそのまま。途中まで足すこともしません)。対応表のファイルを選んだときは、そう出します。頭に BOM の付いたファイル(メモ帳などで保存したもの)も読めます。1字の語が入っていれば、その件数を注意に出します
9. 「置き換える」を押すと、後の欄の下に「辞書に足す候補」が出ます。置き換えで見つからなかった語のうち、会社・団体の名前らしい語の一覧です。探す所は、「商号」「会社名」「下請負人」などの欄の値(`|` 区切り・タブ区切りの表と、「欄名: 値」「欄名 値」の行)と、法人の種類に近い語(社団法人・(同)・Co., Ltd. など)や慣用の語尾(土木・電設・商事など)で終わる語です
10. 候補は自動では置き換えません。選ぶまで、候補の語は後の欄に元のまま残ります。1つずつ「辞書に足す」(会社名として足し、すぐに置き換え直します)か「足さない」を選びます。「足さない」の選びは、ページを閉じるか「対応表と足した語を消す」を押すまで残ります
11. 候補は形と欄から探すだけです。語尾の前が1字の名前(「林土木」の形)や、一覧に無い語尾・欄名の語は出ません。候補が無くても、漏れが無いことは意味しません。候補の表は画面だけの機能で、Claude Code の道具(read_masked)には出ません

ファイルから読む(.txt・.docx・.xlsx・.pdf):
- 「ファイルから読む」でファイルを選ぶと、この端末の中で文字を取り出し、「置き換える文」の欄に入れます(外へは送りません)。中身を確かめてから「置き換える」を押してください
- .txt は UTF-8(BOM の有無どちらも)か Shift_JIS。.docx は本文の段落ごとに1行(表のセルも段落ごと)で、頭書き・脚注があれば後ろに足します。.xlsx はシートの順に、行ごとに1行・セルはタブで区切ります(数のセルは保存された値のまま。日付は数になります)
- 読まないもの: 書式・画像・コメント・変更履歴で消した文字・パスワードのかかったファイル。.doc・.xls は読めないので、文字をコピーして貼り付けてください
- 図形・テキストボックスの中の文字は、順番が崩れたり抜けたりすることがあります。取り出した後の欄を確かめてください
- PDF は文字の入った物だけを読みます。頁の間に「―― 2頁 ――」の行を入れます。読んでいる間は「読んでいます(3/8頁)」と出ます。一部の頁が画像だけなら、その頁の番号を出します
- 見えない字(透明の指定の字・切り抜きだけの字)は入れず、数だけ出します。白い字・頁の外の字・ごく小さい字は見えない字として扱わないので、文に入ります
- 読めない PDF: 紙を写した画像だけ(スキャン)/保護(パスワードやコピーの禁止)つき/字の形しか入っていない/途中で切れた・壊れた/大きすぎる。それぞれ理由と次の手を出し、欄は変えません。保護は解きません。画像の文字は読みません(OCR はしません)
- 字に戻せなかった字が少しだけある PDF は、その字を「�」のまま入れて数を出します。中身の一部が壊れていて読めない所があるときも、そう出します
- 表の PDF は行や列の順が崩れることがあります。取り出した後の欄を紙と見比べてください
- PDF の使い道は、受け取った PDF を外の AI に貼る前に名前を置き換えることです(公告の PDF を段1 の欄に入れる使い方は「公告から条件を拾う」)。台帳の点検の欄は PDF を読みません。下請けから元の Excel をもらって入れてください
- 取り出す部品は `src/mask/extract.mjs`(`extractFile(ファイル名, 中身)` が文字と注意を返し、`extractText` は文字だけを返す)。PDF を読む部品は `src/pdf-read.mjs`

人名の文脈規則(辞書に無い人名を、まわりの語から人名の候補として置き換える):
- 敬称の前: 「甲野様」「甲野 一郎 殿」「甲野氏」「甲野さん」
- 役職の後ろ: 「部長 甲野一郎」「代表取締役 甲野 一郎」「現場代理人 甲野 一郎」(区切りは空白・コロン・縦線・タブ・括弧。括弧は半角の ( と全角の（ のどちらも。例「現場代理人（甲野 一郎）」)
- 欄名の後ろ: 「氏名: 甲野 一郎」「担当者 甲野一郎」「作成者:甲野 一郎」「担当者（乙川）」
- 役職の前: 「甲野 一郎(監理技術者)」のように括弧の中に役職があるもの、「乙川所長に報告」「丙田部長 承認」のように名前に直に付く役職。直に付く形は、姓に付けて呼ぶ役職(所長・部長・課長・社長・職長・工事長 など)だけで、前が部署・場所の語(現場・工事・作業・出張・営業 など)なら人名にしません(「現場所長」「工事部長」はそのまま)
- 並びの2人目以降: 「氏名: 甲野 一郎、乙川 二郎」のように、役職・欄名の後ろの名前に読点(、 , ，)や中黒(・)で並ぶ名前
- 部署の後ろ: 「町 総務課 甲野 一郎(別紙のとおり)」「総務課 甲野 一郎、乙川 二郎」のように、部署の語(〜課・〜部・〜局・〜室・〜係・〜班。語尾の前に2字以上)の後ろの、姓と名が空白で分かれた名前。部署の語と発注者の名前は残します。部署の後ろの1語(「総務課 甲野」)は取りません。部署の中の仕事の語の並び(「企画部 経営 戦略」)は語の一覧で外しますが、一覧に無い語の並びは人名として置き換わることがあります。対応表で確かめてください
- 見つけた語は、同じ文の中の文脈の無い所でも同じ記号にします。対応表の行には、どの規則で見つけたか(確信の弱い語であること)の印が付きます。会社名・辞書に足した語と重なれば、そちらを取ります
- 置き換えすぎを減らすため、役職・欄名そのもの、「未定」「同上」「専任」などの語、名前に付かない字(者・課・部・所・欄・書・号 など)で終わる語は人名にしません。表の見出しの語(年齢・性別・続柄・職種 など)、様式の語(押印・検印・自署・不在・記載省略・自動・「〜予定」など)、部署・仕事の語(設計 など)、職業の名前に「さん」(大工さん・職人さん・監督さん など)も人名にしません。縦線かタブで区切った表の見出しの行(ほかの欄がすべて欄名・役職・見出しの語の行)では、役職・欄名・並びの規則を当てません。前に別の漢字が続く名前(「担当者甲野さん」)、1字の姓だけ(「庚さん」)、カタカナ・ローマ字の名前、文脈の無い人名は見つけません
- 規則は分野の語を持たない別のファイル `src/mask/rules-person.mjs` にあり、建設の役職・欄名(現場代理人・監理技術者・主任技術者・職長 など)は辞書のファイル `src/mask/dict-construction.mjs` から足しています

現場名の語尾の規則(辞書に無い現場名を、語尾から現場名の候補として置き換える):
- 欄名の後ろ: 「工事名: みほん市道 架空3号線 道路改良工事(第1工区)」のように、欄名(工事名・工事名称・件名・現場名・作業所名 など)の後ろにあり、語尾で終わる値を、その欄(行・縦線・タブ)の終わりまで置き換えます。空白・ひらがなを含んでよく、語尾の後ろの括弧も含めます。前の「(仮称)」と欄名は残します
- 語尾: 「甲野川改修工事」「丙田作業所」「甲野川改修工事第2工区」「戊浜倉庫現場」のように、語尾(工事・工区・作業所・現場・JV)で終わる漢字・カタカナ・英数字の並びを置き換えます
- 置き換えすぎを減らすため、名前の部分から一般の語(建設業の許可の業種・工種・「下請」「公共」「当該」「本」など)・数・「第」「年度」・「この」「その」を除いて2字より短く残る語(「下請工事」「土木一式工事」「建設現場」「第2工区」「擁壁工事」、工区の位置・時間・工事の種類の語だけの「上流工区」「夜間工事」「ガス工事」「断熱工事」「事故現場」)は現場名にしません。語尾の後ろに漢字が続くもの(「工事費」「工事業」「現場代理人」)も取りません
- 見つけない・限界: 欄名の無い所の、ひらがなを含む現場名(「みほん市道…」は文脈が無いと「市道…」以降しか見ず、一般の語だけなら取りません)、語尾の後ろに漢字が続く書き方(「甲野川改修工事現場代理人」)、一般の語の表に無い工種の「〜工事」(置き換えすぎになることがあります)。共同企業体(「〇〇JV」)は前からある会社名の形が先に取ります
- 見つけた語は人名の規則と同じく、対応表の行に規則の印が付き(確信の弱い語)、同じ文の中の同じ語も同じ記号にします
- 規則は分野の語を持たない `src/mask/rules-site.mjs` にあり、語尾・欄名・一般の語の表は `src/mask/suffix-construction.mjs` にあります。ほかの業界では、同じ形の表を作って差し替えます

会社・団体の名前の規則(業界を問わない。F24a):
- 法人格のある名前: 「名前 + 法人格」「法人格 + 名前」を〔会社名1〕に置き換えます。法人格は、株式会社・有限会社・合同会社などの会社のほか、一般社団法人・公益財団法人・特定非営利活動法人(NPO法人)・医療法人(社団・財団)・社会福祉法人・学校法人・宗教法人・独立行政法人・国立大学法人・事業協同組合・農業協同組合・農事組合法人・有限責任事業組合・弁護士法人・税理士法人・監査法人・特許業務法人・相互会社など(一覧は `src/mask/company-types.mjs`)
- 略し方と囲み文字: 括弧の中の略し方(「(株)」「(有)」「（一社）」「（公財）」「(特非)」など。括弧は半角・全角、中の空白も可)と、囲み文字(「㈱」「㈲」「㈳」「㈶」「㊑」「㊩」「㍿」など)を法人格として扱います。囲み文字は一覧を手で書かず、U+3200〜U+33FF の字を NFKC で正規化して法人の種類の字・語になる字を拾います(「㈹」(代表)は入れません)
- 様式の印と同じ形の略し方: 「(有)」「(医)」「(学)」「(合)」「(福)」「(宗)」「(独)」は様式の欄の印と同じ形なので、隣に字があるだけでは会社名にしません(「資格(有)」「指導医(医)」「学籍(学)番号」「既往症(有)高血圧」は置き換えません)。「語 + 略し方」は、語が団体の語尾で終わるとき(「乙川建設(有)」)、前に欄名があるとき(「会社名: 甲野(有)」)、後ろが「御中」「代表」「と契約」「に発注」などのときだけ取ります。「略し方 + 語」は、前に字が無いとき、前が欄名か助詞のとき、語が団体の語尾で終わるときだけ取ります。そのため、欄名も語尾も無い「甲野(有)」「みほん会(医)」は漏れ、前に字の無い「(有)高血圧」は置き換えすぎます。「(株)」と囲み文字は今までどおりです
- 空白: 法人格と名前のあいだの空白(半角・全角1字)を許します(「甲野建設 株式会社」「株式会社 甲野建設」)。どちらの側の名前かは、法人格のすぐ隣に名前の字がある側を取り、前の語が欄名(代表者・会社名・発注者 など)なら後ろの名前を、後ろの語が役職など(代表取締役・御中・支店 など)なら前の名前を取ります。様式の「有・無」と紛れるので、括弧の略し方(「健康診断 (有)」)は空白を挟む形では取りません
- ひらがな・カタカナの入る名前: 名前にひらがなが入ってもよくしました(「みほん建設株式会社」「株式会社ふもと野ロジ」)。法人格の前の名前は、漢字・カタカナのすぐ後ろの「は・が・を・に・と・の」や「した・として」などより前を捨て(「当社はみほん建設株式会社」→「みほん建設株式会社」)、法人格の後ろの名前は「は・が・として・です」などから後ろを捨てます(「株式会社さくらは」→「株式会社さくら」)
- 法人格だけの一般の文: 法人格の後ろが文の続きや制度の語のときは取りません(「当社は株式会社です」「株式会社又は合同会社」「株式会社法」「株式会社設立」)。「株式会社甲野及び株式会社乙川」は2つの名前として取ります
- 法人格の無い団体・施設: 法令で名前が決まった施設(学校教育法 第1条の学校、医療法の病院・診療所、老人福祉法・介護保険法の老人ホーム・介護老人保健施設・介護医療院 など)と、慣用の語尾(組・建設・工務店・商店・製作所・工業・産業・事務所・クリニック・薬局・協会・組合・役場・市役所・県庁・町内会 など)で終わる語を、確信の弱い語(〔会社名1〕。見つけ方「法人格の無い団体・施設の語尾」)として置き換えます。名前のひらがなは頭だけ許します(「ひまわり幼稚園」「みほん町役場」)
- 置き換えすぎを減らすため、語尾の前の名前から一般の語(県立・市立・総合・大学・現場・本社・設計・法律・労働・建設・地域・医療 など)・数・「第」を除いて2字より短く残る語(「県立高等学校」「現場事務所」「第一小学校」「労働組合」「地域産業」「大学病院」)、語尾の後ろに漢字が続く語(「建設業」「組合員」)は取りません。「当該株式会社」「独立行政法人等」のように名前が一般の語だけのものも取りません
- 語尾の規則だけで除く語: 工事の対象・産業・役所の言い方・診療の種類の語(鉄道・ダム・学校・橋梁・石油・成長・監督員・振興局・矯正・動物 など)と人数(二人 など)も除きます(「鉄道建設」「成長産業」「監督員事務所」「二人組」「動物病院」は取りません)。実在の県の名前 +「県庁」も取りません。法人格のある名前(「ダム株式会社」)には使いません。一覧の語でできた本物の会社名(例「鉄道建設」という社名)は法人格が無いと漏れます。一覧は建設と医療でよく出る語で、全部の業界を覆うものではありません
- 語尾が前に来る施設: 施設の種類の語の後ろの名前も取り、種類の語と合わせて1つに置き換えます(「デイサービスセンターひまわり」「特別養護老人ホームさくらの里」「グループホーム甲野」)。すぐ後ろが利用者・入居者・職員・施設・運営・定員などの語や文の続きなら取りません(「グループホーム入居者」「特別養護老人ホームがあります」)。施設の語尾なら名前の途中のひらがなも入れます(「さくら市立ひまわり幼稚園」「甲野ひまわり幼稚園」)。途中のひらがなは3字以上で、活用の字で終わらないものだけです(「大きな病院」「通っている幼稚園」は取りません)。「園」「苑」「荘」「寮」「の里」「ホーム」「センター」などで終わる短い名前は一般の語が多いので、社会福祉法人・医療法人・学校法人などの名前の空白の後ろだけで取ります(「社会福祉法人みほん会 ためし園」。公園・保育園などは除きます)
- 施設の名前の限界: 法人の名前から離れた「ためし園」(「社会福祉法人みほん会が運営するためし園」)、1字の名前(「グループホーム森」)、途中のひらがなが活用の字で終わる名前(「甲野あおい幼稚園」)は漏れます。名前の途中の「は・の」などで切れることがあり、「さくら市立はなぞの幼稚園」は「さくら市立は」が残ります
- 業界の表との関係: 医療(例)では、病院・クリニックなどは医療の施設名の規則(〔施設名1〕)が先に取ります。建設では、この規則で〔会社名1〕になります
- 限界: 名前の中の「漢字 + の・と」はそこで切れ、前の部分が残ります(「日本の森株式会社」は「森株式会社」だけを置き換え、「森の家工務店」は「家」が2字に足りないので取りません)。ひらがなの後ろの「と・の・に・で」は名前の一部とみなすので、「株式会社さくらと契約」は「と契約」まで置き換えます(漏らすより置き換えすぎの方にしています)。ひらがなだけの文に続く名前(「わたしたちはさくら建設」)は文まで置き換えます。1字の名前に語尾が付く語(「林建設」)、一般の語の表にある語を使った名前(「日本建築協会」)は取りません。法人格の種類の名前は出典の一覧から入れましたが、出典の原文とは照合していません
- 語尾「電設サービス」の限界(F75a): 語尾の前が「屋内」「構内」「高圧」「低圧」「第二種」のような普通の語でも、会社の名前として〔会社名1〕に置き換わります(「屋内電設サービスの範囲を確かめる」→「〔会社名1〕の範囲を確かめる」)。普通の語が記号になる側の失敗で、名前が漏れる側ではありません。置き換えすぎを見張る14文(`tests/unit/mask-e2-leak.test.mjs`)には「電設サービス」の字が無いので、14文ではこの形は見つかりません。この5語は14文の語に「サービス」を付けた作文で、実在の文では確かめていません
- 語の一覧(出典つき)は `src/mask/company-types.mjs`、規則は `src/mask/rules-company.mjs` です。語を足すときは一覧のファイルだけを直します

住所の規則(業界を問わない。F24b):
- 並び: 〒 郵便番号 → 都道府県 → 郡・市・区・町・村 → 町名(大字・字を含む)→ 丁目 → 番地・番・号 → 枝番 → 建物名 → 部屋番号を、1つの〔住所1〕にします(「〒000-0000 架空県みほん市さくら町1-2-3 みほんビル 3階 301号室」)
- 都道府県を書かない住所: 市区町村 + 町名 + 番地を取ります(「みほん市さくら町一丁目2番3号」)。番地は「丁目・番地・番・号」が付くか、数が2つ以上つながるか、町名が「町・村・字」で終わるときだけ取ります(「みほん市 3」「みほん市 2026年度」は取りません)。市区町村の名前の頭の「は・で」などの文の語や、「所在地」などの欄名は外します(「工事はみほん市…」→「みほん市…」)
- 空白: 部分のあいだの空白(半角・全角1字)を許します(「架空県みほん市 さくら町 0-0-0」「架空県 けんちょう通り 0-0」)
- 数字とハイフン: 半角・全角・漢数字(漢数字は「丁目・番・号・の」が続くときだけ)、ハイフンは - − ‐ – ー － ― を許します
- 建物名: ビル・ビルディング・マンション・ハイツ・コーポ・アパート・レジデンス・ハイム・荘・団地・住宅・寮などで終わる語と、コーポ・メゾン・ハイツで始まる語。部屋番号は建物名の後ろなら数だけでも、建物名が無ければ「号室・階」の付くものだけ取ります
- 〒と郵便番号: 「〒000-0000」は単独でも取ります。〒の無い「000-0000」は「郵便番号」の欄名の後ろだけです
- 続く名前を食わない: 住所は番地(か建物名・部屋番号)で終わり、後ろの会社名・人名・電話番号は入れません。建物名に見える語に法人の種類(株式会社 など)が入るときは会社名として分けます。「架空県 架空県ためし市0-0」のように都道府県の後ろの空白のあとに都道府県名で始まる語が来るときは、前の都道府県(発注者の名前)を住所に入れません。都道府県 + 市区町村だけ(「架空県みほん市」)は発注者の名前とみなし、住所の欄名(住所・所在地・本店 など)の後ろのときだけ取ります。「みほん市長」「みほん市役所」は住所にしません
- 条丁目と京都の通り名: 「北8条西5丁目1-1」「南1条西2丁目」「4条通8丁目」は全部を1つの住所として取ります。「寺町通御池上る上本能寺前町488」のように上る・下る・東入る・西入る(カタカナの形も)があれば、町名が長くても全部を1つに取ります。一部だけ残さないため、取れないときは全体を取りません。「条例3条」のように法令の語の後ろの条は住所にしません
- 番地の無い住所: 都道府県があれば町名の「町・村・丁目」までを取ります(「架空県みほん市さくら町にある」→「架空県みほん市さくら町」)。都道府県が無ければ「地内・地先」で終わるときだけ取ります(「みほん市さくら町地内」)
- 置き換えすぎを減らすため、「都市・地区・工区・学区・特区・市町村」など、市・区・町・村で終わるが市区町村の名前ではない語は市区町村にしません(「第3工区 1-2」「都市計画 1-2」を取りません)
- 条と通り名の限界: 番地も丁目も無い漢数字の条(「札幌市中央区南一条」)、都道府県も番地も無く、市区町村が1つだけの通り名(「みほん市烏丸通御池」)は取りません。通りの名前にひらがなが入ると、上る・下る を見ません。「さくら町の工事を上る」のような文を取らないためです
- 限界: 町名が「町・村」で終わらず市区町村も無い住所(「さくら台1-2-3」だけ)、番地も「町・村・丁目」も無い町名(「架空県みほん市さくら台」)、都道府県も番地も無い住所(「みほん市さくら町」)は取りません。都道府県の名前は、47都道府県の一覧のほかは「漢字2字 + 県」だけを取ります。建物名は語尾の表にある語だけで、語尾の無い建物名は残ります。番地の直後に空白なしで会社名が続くと(「…1-2-3甲山建設株式会社」)、会社名の頭が数字と一緒になり、住所の方を取って会社名が残ることがあります。初めて見る書類4件の住所4語は、2026-11-04 の測り直しでは元のまま残りませんでした(一部だけ残った語の数は受け取っていません)
- 規則と出典の URL は `src/mask/rules-address.mjs` にあります

業界の切り替え(建設・医療(例)):
- 「業界(語尾・役職の表)」で「建設」(はじめの選び)か「医療(例)」を選びます。医療(例)では、病院・医院・クリニック・診療所・薬局・歯科医院・訪問看護ステーションなどで終わる語を施設名の候補(〔施設名1〕)として、医師・主治医・看護師長・薬剤師などの役職や「患者氏名」などの欄名の後ろの語を人名の候補として置き換えます。「総合病院」「調剤薬局」「大学病院」のように一般の語だけの名前は取りません
- 医療(例)は、語尾の規則が建設のほかの業界でも差し替えて使えることを示す「例」の表です。医療の書類での漏れの率は測っていません(この節の限界の数字はすべて建設の書類のものです)。医療の書類で使うときは、後の欄を必ず目で確かめてください
- 医療(例)では、建設業の許可番号・共同企業体の形は使いません。会社名・住所・電話・メールなどの分野によらない形は同じです
- 切り替えると、足した語はそのまま新しい表で使い、対応表・確かめてほしい語の選び・前後の欄は消します。対応表があるときは確かめを出すので、戻す文があるときは先に「対応表を書き出す」で保存してください
- 表は `src/mask/suffix-medical.mjs`(語尾・欄名・一般の語)と `src/mask/dict-medical.mjs`(役職・欄名・止める語)にあります。建設の表(`src/mask/suffix-construction.mjs`・`src/mask/dict-construction.mjs`)と同じ形です

見本の語を混ぜて見落としを測る(F28a):
- 「置き換える」を押すたびに、架空の人名・会社名・住所を種類ごとに2語、合わせて6語作り(見つけやすい型)、貼った文の後ろに見えない形で混ぜてから、置き換える所を探します。混ぜた語の字が全部置き換える所に入ったかを数え、「置き換える」の下に「確かめのための見本: 見つけやすい型 6/6・見つけにくい型 1/6」のように、置き換えた数/混ぜた数を出します。見つけやすい型で残った見本があれば「注意:」として種類・型・語を出します(見本は架空なので語を出しています)
- 型は毎回、乱数で選び直します。人名は「担当者: 姓 名」「姓 名 様」「部長 姓名」「氏名：姓 名」「姓 名(課長)」、会社名は「株式会社〇〇」「〇〇株式会社」「㈱〇〇」「(有)〇〇」「一般社団法人〇〇協会」「合同会社〇〇」、住所は「〒と郵便番号つき」「丁目・番地・号(漢数字)」「空白で区切る」「建物名と部屋番号」「都道府県を書かない」から、種類ごとに重ならないように2つずつ選びます。名前の部品は甲野・乙川・みほん市・さくら町などの仮の語です(`src/mask/decoy.mjs`)
- 見つけにくい型(F31d): 同じやり方で、規則の手がかりが少ない形も種類ごとに2語、合わせて6語混ぜ、見つけやすい型とは別に数えます。人名は「文脈の無い姓名(姓 名だけの行)」「文の中の姓名(敬称・役職なし)」「姓だけ」「表の中の名前(見出しの下の行)」「タブで区切った表の名前」、会社名は「法人格も語尾も無い社名」「表の中の法人格の無い社名」「ひらがなの屋号」「表の中の語尾のある社名」、住所は「番地の無い住所(市と町だけ)」「町名だけ」「表の中の番地の無い住所」「都道府県と市だけ」「都道府県から書いた番地の無い住所」です。残った形は「見つけにくい型で残った形:」として型の名前だけを出します
- 見つけにくい型には、今の規則で取れる形(語尾が一覧にある社名、都道府県から書いた住所)と取れない形の両方が入っています。どの型を引くかで数字が変わるので、毎回同じ数にはなりません。低いのは道具の不具合ではなく、この形の語は文にあっても残りやすいという知らせです。見つけにくい型の結果は漏れの目安で、保証ではありません
- 2つの組は別々に探します。見つけやすい型の文脈で見つけた語が、同じ語の見つけにくい型を「2か所目」として取って結果が甘くなるのを避けるためです。部品の語も分けてあります
- 混ぜた語は、利用者に見せる置き換えとは別に「置き換える所を探す」だけで数えるので、後の欄・対応表・記号の番号・書き出す対応表に入りません。足した語・業界の表は、そのときのものを使います
- プラグインの道具 `read_masked` も、1つ目の文(置き換えた中身。今までと同じ)に続けて、2つ目の文に同じ結果を返します
- 空港の手荷物検査で、検査の画面に偽の危険物の画像を時々混ぜ、見落とさずに見つけたかで検査の確かさを測るやり方(Threat Image Projection)から借りました
- 限界: 見つけやすい型は、この道具が扱うと説明している形から選んでいます。見本が全部置き換わっても、書類の中のほかの形の名前が残っていないことは示しません。見つけにくい型も語数が少なく(1回6語)、型の表にある形だけなので、漏れの率の測り直しの代わりにはなりません(率は [mask-rate.md](mask-rate.md))。見本は文の後ろに足すので、表の形の型も、文の後ろに足した小さな表で試すだけで、書類の中の表そのものは試していません。後の欄は必ず目で確かめてください

元に戻す前の点検(F28b):
- 「置き換える」を押したとき、確かめてほしい語で「置き換える」「残す」を選び直したとき、「元に戻す」を押したときに、後の欄(外へ貼る文)を対応表のすべての語(元の語と、ほかの書き方)で探し直し、「置き換える」の下に「元に戻す前の点検: 後の欄に、対応表の元の語は残っていません」か「注意: … n か所残っていました: 「残った書き方」(記号 の元の語「…」)」を出します
- 探すときは、後の欄と元の語の両方を、全角・半角(NFKC)、空白(全角の空白を含む)を消した形、ハイフンの字の違い(数字に挟まれた長音「ー」を含む)、英字の大文字・小文字をそろえてから比べます。記号(〔人名1〕など)の中は探しません。重なるときは長い語だけを数えます
- 対応表には、同じ画面で前に置き換えた文の語と、読み込んだ対応表の語も入っています。前の文で見つけた名前が、次の文で文脈の無い書き方で出て置き換わらなかったときも数えます
- 数えないもの: 確かめてほしい語で「残す」を選んだ語(わざと残した語)、1字の語(ほかの語の一部にも当たるため。数を出します)
- 残っていたら、その書き方を辞書に足して「置き換える」をもう一度押してください。点検は探すだけで、後の欄・対応表は変えません
- 限界: 探すのは対応表にある語だけです。一度も見つけていない名前(辞書にも規則にも当たらない名前)が残っていることは示しません。読み仮名・略称など、字の違う書き方も探しません

確かめてほしい語(規則だけで見つけた語)を1件ずつ選ぶ:
- 人名の文脈規則・現場名の語尾の規則だけで見つけた語(辞書・形では見つからなかった語)は、後の欄で印を付けて出します。辞書に足した語・会社名や電話などの形で見つけた語には印を付けません
- 後の欄の下の「確かめてほしい語」の表に、記号・種類・元の語・見つけ方・状態が並びます。1件ずつ「置き換える」か「残す」を選びます。「残す」を選んだ語は、後の欄で元の語に戻します(名前でない語を置き換えていたときに使います)。選び直せます
- 選ぶまでは「未確認」です。未確認の語が残るうちは、「元に戻す」の欄の上に「未確認の語があります(○件)」と出します。すべて選ぶと消えます
- 選びはこの画面のメモリの中だけに持ちます(ブラウザに保存しません)。同じ文で置き換え直しても残り、「対応表と足した語を消す」か「対応表を読み込む」で消えます。書き出す対応表のファイルには選びを入れません
- 選びはこのツールの判定ではありません。「置き換える」を選んでも、ほかの所に残った名前は見つけません。後の欄を必ず目で確かめてください

注意:
- 置き換えには漏れがあります。漏れは0になりません。辞書に無い人名・現場名、ひらがなを含む会社名、形の決まっていない書き方(番地の無い地名など)は残ることがあります。外へ出す前に、後の欄を必ず目で確かめてください
- 書き出した対応表のファイルと辞書のファイルには元の名前が入っています(書き出すときに画面にも出します)。外の AI などへ送らず、要らなくなったら消してください
- 記号にしても、残った語の組み合わせ(工期・金額・地名・工種・発注者など)から、どの工事か・誰のことかが分かるおそれがあります

## Claude で点検(手元のプログラム)
画面は外へ通信しません。Claude での点検は、手元の node のプログラム `tools/claude-check.mjs` が行います。送るのは、「A. 文の置き換え」で置き換えた後のファイルだけです。

1. 画面で置き換えた後の文をファイルに保存し、「対応表を書き出す」で対応表も保存する(対応表は漏れの検査にだけ使い、送りません)
2. API の鍵を環境変数 `ANTHROPIC_API_KEY` に入れる(鍵はファイルに書かない。例 `export ANTHROPIC_API_KEY=xxxx`)
3. `node tools/claude-check.mjs <置き換えた後のファイル>... --map <対応表.json> --out <結果.json>` を動かす
4. プログラムは送る前に、置き換え漏れの検査をもう一度します(対応表の元の語と、メール・電話・会社名・住所・許可番号の形)。残っていれば、中身を表示せず・送らずに止まり、ファイル名・行・種類だけを出します
5. 漏れが無ければ、送る中身(Messages API の本文)を全部表示します。「送る」と打ったときだけ、1回だけ送ります。それ以外は送りません
6. 返事の候補は1件ずつ「AI の候補」と付けて表示し、`--out` のファイルに書き出します。画面の「B. Claude で点検した結果(AI の候補)」の「AI の候補を読み込む」でそのファイルを選ぶと、法令と共通仕様書の決まりで判定した結果(「1.」〜「3.」)とは別の欄に出ます

注意:
- AI の候補は、法令の決まりで判定した結果ではありません。AI が挙げた根拠の条は、このツールでは原文と照らしていません。根拠の書かれていない候補は除きます
- 記録(端末への出力)には、鍵・対応表・元の語を出しません
- `raw/` の中のファイルは送りません
- 使うモデルは `claude-opus-5-5`。送り先は `https://api.anthropic.com/v1/messages` だけです
- 置き換えの漏れは0になりません(上の「文の置き換え」の注意)。送る中身を表示したときに、目で確かめてください

### 絞っていること
- 鍵: `ANTHROPIC_API_KEY`・`ANTHROPIC_AUTH_TOKEN` を外してから `claude` を動かします。端末に鍵が入っていても送られません。記録の `apiKeySource` が `none` でなければ注意を出します
- 道具: `--permission-mode dontAsk` で、`--allowedTools` に挙げた物のほかは断ります。挙げたのは、Skill `construction-check`、`read_masked`・`list_masked`・`check_articles`、係 `refuter`、Skill のフォルダの読み取り、作業フォルダの `tmp/` の読み書きです。`Bash` は挙げていません(F56a で、条番号の確かめを `check-articles.mjs` の実行から道具 `check_articles` に替えました)
- 二重の守り: `--disallowedTools` が断るのは、`Read`・`Edit` の `raw/` への操作と、`WebFetch`・`WebSearch` です。`Bash` などほかの道具はこの指定の範囲の外で、上の `--allowedTools` に無いので断られます。プラグインは権限の決まりを配れませんが、この入口ではコマンドの指定で渡せます。プラグインのフックも同時に働きます
- 保存: `--no-session-persistence` で Claude Code のセッションを保存しません。残るのは上の記録だけです

### API の版との違い
| | API の版(`tools/claude-check.mjs`) | 画面なしの版(`scripts/claude-headless.mjs`) |
|---|---|---|
| 認証 | 環境変数の API の鍵 | Claude Code のログイン |
| 渡す書類 | 人が置き換えた後のファイル | `raw/` の書類を、道具 `read_masked` がその場で置き換えて渡す |
| 送る前の確かめ | 漏れの検査のあと、送る中身を全部見せ、人が「送る」と打つ | 無い。`read_masked` の返事はそのまま Claude に渡る |
| 点検の中身 | 1回の問い合わせ。道具は使わない | Skill の手順。取得した条の原文を読み、条番号をスクリプトで確かめ、反証の係が見直す |
| 結果 | 「AI の候補」の JSON。画面の「AI の候補を読み込む」で読める | Markdown の文と記録。画面では読み込めない |
| 残る記録 | `--out` の結果のファイル | どの道具・どの係を呼んだかが分かる記録 |

実際の書類に使うなら、送る中身を人が見られる API の版の方が慎重です。画面なしの版は、人の確かめが無いので、まず架空の書類で試してください。

### 確かめたことと限界
- 確かめたこと(2026-11-04、Claude Code 2.1.317): 通信を止め、ログインもしていない環境で、架空の書類を置いて1回動かしました。Claude はここで「Not logged in」と答えて終わり、モデルは呼んでいません。その記録の最初の行で、指定がすべて受け付けられ、`permissionMode` が `dontAsk`、`apiKeySource` が `none`、MCP の接続、`list_masked`・`read_masked` の道具の名前、Skill と係の名前を見ました
- 確かめたこと: 上の記録のとおり、架空の書類 E1 の2件では、許可の決まりが当たり、点検が最後まで通りました。ほかの書類では試していません。足りない許可があれば「断られた道具」の注意に出ます
- 道具の一覧では係を呼ぶ道具が `Task` の名前で出るので、許可には `Agent(...)` と `Task(...)` の両方を挙げています
- `--allowedTools`・`--disallowedTools`・`--permission-mode dontAsk`・`--max-budget-usd` は、`claude --help` の説明と上の確かめによります。公式のページ https://code.claude.com/docs/en/headless は作る係の環境から開けなかったので、ページとは照らしていません。`--max-budget-usd` の説明は API の呼び出しの額で、ログインのプランで上限として効くかは確かめていません
- ログインのプランでの書類の扱いが、上の「API に送った内容の扱い」と同じとは限りません。使う前に Claude Code の公式の文書と、利用しているプランの規約で確かめてください
- 記録には、置き換えた後の書類の中身が入ります。置き換えの漏れは0になりません。書類のファイル名は置き換えないので、そのまま Claude と記録に渡ります。記録は外へ渡さないでください
- 記号の元の名前の対応表を使うときは、端末の環境変数 `MASK_MAP`・`MASK_DICT` がそのまま道具へ渡ります
- 画面なしでは聞き返しに答えられないので、頼む文で「聞き返さず、判断できないと書いて進める」よう頼んでいます。止まらないことの保証ではありません

## Claude Code に組み込む
Claude Code で書類を点検するときに、`raw/` に置いた生のファイル(元の名前が入ったもの)を Claude Code の道具で読む操作の多くを止め、置き換えた後の中身だけを渡すための設定と道具です。置き場は `integration/claude-code/` で、自分の作業フォルダに中身を写して使います。

- `.claude/settings.json`: `permissions.deny` で `raw/` の Read と Edit を止める。PreToolUse と UserPromptSubmit で下のフックを動かす。sandbox を有効にする
- `hooks/guard-raw.mjs`: Read・Grep・Glob などが `raw/` を指すと止める。プロンプトの `@raw/…` のようなファイルの取り込みも止める。入力が読めないときも止める。作業フォルダ(3階層まで)に `raw/` があるときは、`raw` の文字を含まない操作も見る(F27a):
  - グロブが `raw/` に当たる形(`cat r?w/a.txt`・`cat */a.txt`・`**/*.txt`・PowerShell の `gc .\r*\a.txt` など)
  - 探す場所を指定しない、または `raw/` を下に持つ場所を探す再帰の検索・一覧・写し(`grep -r`・`rg`・`find`・`tree`・`ls -R`・`Get-ChildItem -Recurse`・`cp -r` など)
  - `node -e`・`python -c`・`bash -c`・`pwsh -Command` などのその場のコード、変数・コマンドの置き換え(`$D`・`$(…)` など。`$HOME` などよく使うものは除く)、`xargs` など読むファイルを前のコマンドから受け取る形
  - 書いたスクリプトの実行(`node read.mjs`・`./show.sh` など)。中身にファイルの読み取り・コマンドの起動の関数があれば止め、シェルのスクリプトは中身のコマンドを同じ決まりで判断する。プラグインのフォルダ(`CLAUDE_PLUGIN_ROOT`)のスクリプトは中身を見ずに通す(点検の Skill の `check-articles.mjs` を止めないため)
  - シンボリックリンクは実体のパスで判断し、`RAW`・`Raw` のような大文字も `raw` とみなす
  - Write・Edit は、書く中身に `raw/` を読む形(`raw/` の指定+スクリプトのファイルか、読み取りの関数)があれば止める。指摘の文に `raw/` のファイル名が出るだけなら通す
  - 止めたときは理由と「人が中身を確かめて、必要なら自分の端末で実行してください」を出す(人に回す)
- `.mcp.json` と `mcp/masked-files.mjs`: 手元の MCP の道具 `masked-files`。道具 `read_masked` は `raw/` の中の文のファイルを読み、人名・会社名・メール・電話・住所・許可番号などを記号に置き換えた後の中身だけを返す(対応表と元の語は返さない。`raw/` の外は読まない。外部と通信しない)
  - 文字は UTF-8(BOM の有無どちらも)→ Shift_JIS の順に読む(F63a)。Excel の既定で保存した CSV・TXT は Shift_JIS になることがあります。どちらでも読めないファイル(UTF-16 など)は中身を返さず、「文字のファイルとして読めません」と返す。文字コードの判別はしていないので、EUC-JP の短い文は Shift_JIS として読めてしまい、化けたまま返ることがある。Shift_JIS を持たない Node では UTF-8 だけを読み、「この Node では Shift_JIS を読めません」と返す
  - Claude Code は道具の返事が長いとファイルに保存して会話にはパスだけを残す(公式 https://code.claude.com/docs/en/mcp。上限を決めていない道具は 50,000字。保存先は Claude Code の側のファイルで、場所は公式に書いていない)。同じページは返事を既定で 25,000 トークンに制限し `MAX_MCP_OUTPUT_TOKENS` で変えられるとも書く
  - `read_masked` は 1MB までのファイルの中身を返すので、置き換えた後の文がこの保存に残ることがある。「入れた書類を保存しない」は画面の決まりで、この保存は Claude Code の側の動き
  - 道具 `list_masked` は `raw/` の中のファイルの名前(作業フォルダからのパス。例 `raw/台帳.txt`)の一覧だけを返す(F23a)。中身は開かない。`raw/` の外の名前は返さず、`raw/` の外へ出るシンボリックリンクは挙げない。読めない形(.pdf など)は分けて挙げる。点検する書類の名前が分からないときに使う
  - 注意: `list_masked` はファイルの名前を置き換えずに返します(`read_masked` に渡すため)。ファイル名に人名・会社名・現場名などの個人情報が入っていると、その名前がそのまま Claude に送られます。`raw/` に置くファイルの名前は `台帳.txt`・`通知書_工事A.csv` のように、個人情報を含まない名前にしてください
  - 道具 `check_articles` は、渡された指摘の文(引数 `text`)の条番号が取得した原文にあるかを確かめ、条番号ごとの結果と数だけを返す(F56a)。ファイルは読まない。確かめるのは条・項・号・細分があることだけで、指摘の中身が条の文に合っているかは確かめない。原文は `plugin/skills/construction-check/reference/sources/` のものを使う

使い方:
1. 作業フォルダに `raw/` を作り、生のファイルを置く(Excel・Word は文のファイル .txt・.csv などにしてから置く)
2. `integration/claude-code/` の `.claude/`・`.mcp.json`・`hooks/`・`mcp/` を作業フォルダに写す
3. 環境変数 `MASK_TOOL_DIR` にこのツールのフォルダを入れる(道具が `src/mask/` を使うため)。人名・現場名は辞書に足さないと見つからないので、画面の「対応表を書き出す」で保存した対応表を `MASK_MAP` に指定すると、その語も同じ記号で置き換える。画面の「辞書を書き出す」で保存した辞書のファイル(`format: "mask-dict"`)を `MASK_DICT` に指定すると、辞書に足した語も置き換える(F28c。対応表と両方を指定したときは、対応表の記号を使い、辞書の語を加える)。辞書を読めないとき(ファイルが無い・形が違う・対応表のファイルを渡した・1MB を超える)は、置き換えずに中身を返すことはせず、理由の種類だけを返す。辞書の語とファイルの名前は返す文にも道具の出力にも出さない
   - `.mcp.json` の `env` に `"MASK_DICT": "${MASK_DICT:-}"` を足してください(`MASK_MAP` と同じ書き方)。足していないときに Claude Code が端末の環境変数を道具へ渡すかは確かめていません
4. 作業フォルダで Claude Code を開き、「raw/台帳.txt を read_masked で読んで点検して」のように頼む

限界(必ず読んでください):
- コマンド(`cat`・`type`・`Get-Content` など)での読み取りは、Linux・WSL で Claude Code の sandbox が有効なときは、`permissions.deny` の Read の決まりが sandbox にも使われるので止まります。Windows(ネイティブ)では sandbox が使えないので止まりません。フックはコマンドを簡単に読むだけなので、止めきれない操作があります。わかっているもの:
  - 別名(alias)・シェルの関数、`npm run`・`make` などのタスクの中身、`sed` の `r` コマンドなど、コマンドの中から別のファイルを読む形
  - 自作のスクリプトの読み方にも限界があります。中身と、静的な `import`・`require` の相対パス、Python の手元の `import`、`node -r`・`--import` で読み込む別のファイルは文字で探しますが、パッケージの名前で読み込むもの(`node_modules` の中)、`NODE_OPTIONS` など環境変数で読み込ませる形、Ruby・PHP・Perl などの読み込み、`const r = require` のように別名を付けた読み込みは見ていません
  - 作業フォルダから4階層より深い所の `raw/`(パスに `raw` の文字があるときだけ止める)
  - 先に作ったリンク・写し(人が端末で作ったもの)を、別の名前で読む形の一部
  - プラグインのフォルダのスクリプトは中身を見ずに通すので、そのスクリプトに `raw/` の外のパスを渡しても読む中身は確かめない
  - MCP の道具はフックの対象にしていない(`masked-files` の `read_masked` は置き換えた後の中身だけを、`list_masked` は `raw/` の中のファイルの名前だけを返す。名前は置き換えない。`check_articles` は渡された文の条番号を確かめた結果だけを返し、ファイルを読まない)
  - 止めすぎもあります: `raw/` がある作業フォルダでは、場所を指定しない `ls -R`・`grep -r`、変数の入ったコマンド、ファイルを読む自作のスクリプト(`import`・`require` で読み込んだ別のファイルの中で読むものを含む。ただし上の「わかっているもの」の形は見ていないので、自作のスクリプトがすべて止まるわけではありません)も止まります。読み込む別のファイルが見つからないときも、確かめられないので止めます。`claude -p` では止まったところで先へ進めません
- Grep は、探す場所から3階層までに `raw/` があるときにフックで止めます。それより深い所の `raw/` は `permissions.deny` に任せます
- 止めるのは Claude Code の道具だけです。人が端末で開いたファイルや、別のプログラムは止められません
- 置き換えの漏れは0になりません(上の「文の置き換え」)。返ってきた中身に元の名前が残っていないか、目で確かめてください
- 試験(`tests/acceptance/claude-code.test.mjs`)は、フックの判断と道具の返事を関数として確かめたものです。Claude Code の版が変わるとフックの入力の形が変わることがあります

## Claude Code のプラグイン(plugin/)
上の「Claude Code に組み込む」の守り(フック)と道具(`masked-files`)を、作業フォルダに写さずに使えるよう、Claude Code のプラグインの形にまとめたものです。置き場は `plugin/` です。

- `.claude-plugin/plugin.json`: プラグインの名前(`motouke-navi-guard`)などの宣言。`.claude-plugin/` にはこのファイルだけを置き、ほかの部品はプラグインの直下に置く。`version` はプラグインの版ですが、画面の足と印刷の頭に出す版も同じ番号にします(`node build.mjs` がここから読みます)。変更の記録は `CHANGELOG.md` にあります
- `hooks/hooks.json`: PreToolUse(Read・Grep・Glob・Bash・PowerShell・Edit・Write・NotebookEdit)と UserPromptSubmit で `${CLAUDE_PLUGIN_ROOT}/scripts/guard-raw.mjs` を動かす。`raw/` を指すと終了コード 2 で止め、理由を標準エラーに出す
- `.mcp.json`: 道具 `masked-files` を `${CLAUDE_PLUGIN_ROOT}/mcp/masked-files.mjs` で起動する。`MASK_TOOL_DIR` にプラグインのフォルダを渡し、プラグインの中の `src/mask/` で置き換える。`env` の `"MASK_DICT": "${MASK_DICT:-}"` で、端末の環境変数 `MASK_DICT`(辞書のファイルのパス)を道具へ渡す(F35b)。入れないと空が渡り、辞書なしで動く。同じ書き方の使い捨てのプラグインを `claude --plugin-dir <フォルダ> mcp list` で起動し、Claude Code 2.1.317 が値と空を道具へ渡すことを確かめた(2026-11-04)。このプラグインで Claude に `read_masked` を呼ばせて通しては確かめていない(上の「使い方」の 3. は作業フォルダに置く `.mcp.json` の場合で、こちらの `env` には `MASK_DICT` が無いので足す必要がある。道具が `MASK_DICT` を読むことは、道具を直接動かす試験で確かめました)
- `scripts/guard-raw.mjs`・`mcp/masked-files.mjs`・`src/mask/`: `integration/claude-code/` と `src/mask/` の写し。プラグインは入れたときに別の場所へ写されるので、置き換えの部品も中に置いている。元を直したら `node scripts/sync-plugin.mjs` で写しを作り直す(写しが元と同じことは `tests/unit/plugin-structure.test.mjs` で確かめる)

- `skills/construction-check/`: 建設の書類を点検する Skill(F20b)
  - `SKILL.md`(500 行以内): 書類は道具 `masked-files` の `read_masked` で置き換えた後の中身だけを読み、取得した条に照らして抜けや食い違いの「候補」を、法令名・条・項・号と原文の短い抜き書きつきで書く手順。見ていない条は根拠にせず人に回す。候補を出したあと反証の係 `refuter` に見直させ、「確かめられない」とされた候補を指摘の一覧から外して「外した候補」として別に見せる(F35b。外した候補は消さない)
  - `reference/articles.md`: この Skill に入れた8つの条(建設業法 第3条・第24条の8・第26条、建設業法施行令 第2条・第7条の4・第27条、入札契約適正化法 第15条、建設業法施行規則 第14条の2)の作る側の言葉での要約と、見ていない条の一覧(取得した条の中から引かれている条)。要約は入口で、根拠は原文
  - `reference/sources/`: 取得した法令の原文と取得日の一覧(`data/sources/` の写し)
  - `scripts/check-articles.mjs`: 点検の結果(文か JSON)に書かれた条番号が、取得した原文にあるかを確かめる。Skill の手順では、MCP の道具 `check_articles`(引数 `text`)が同じ処理を呼び、条番号ごとに「ある」「無い」(取得していない条・無い項や号)「確かめられない」(「法第○条」「同条」のように法令名が無い)と数を返す(F56a)。道具の返事に原文の全文は入らない。部品か原文が見つからないときは、どの条番号も確かめていないと返す。項・号の切り出しは `src/quote-check.mjs` の写し(`lib/quote-check.mjs`)を使う
  - 端末で確かめる別の道: `node plugin/skills/construction-check/scripts/check-articles.mjs <指摘のファイル>` で同じ文が出る。1つでも「ある」以外があれば終了コード 1
  - `scripts/check-done.mjs`: Stop のフック(F56b)。`read_masked` を呼んだ会話で、最後の返事に係の結果の数(残る・崩れた・確かめられない)も「反証の見直しをしていない」も無いとき、Claude に案内の文を渡して1回催促する。`SKILL.md` の frontmatter の `hooks:` で登録する。限界は下の「手順の抜けの催促の限界」

- `skills/spec-to-rules/`: 発注者の仕様書の文から規則表の行を作る Skill(F26a)
- `skills/bid-intake/`: 公告・入札説明書・仕様書から条件を拾う Skill(F41a。下の「公告から条件を拾う」)
- `skills/estimate/`: 数量の表の行を施工パッケージに当てて参考の額を出す Skill(F42b。「数量の表から参考の額を出す」)
  - `SKILL.md`(500 行以内): 利用者が渡した仕様書の文(公開資料なので置き換えない。`raw/` には置かない)から、段取りの行(`data/schedule.json` と同じ形)と施工計画書の記載項目の行(`data/plan-items.json` と同じ形)を、原文の抜き書きつきで作る手順。原文から決められない欄は値を「判断できない」にして理由を書く。原文に無い行は作らない

### 手順の抜けの催促の限界
`check-done` は、Stop の時点で最後の返事の文を見て案内を渡す、一度だけの催促です。手順6・7 を守らせる仕組みではありません。止める所(`raw/` の読み取り)は `guard-raw` が持ちます。

- 文しか見ません: 道具や係を実際に呼んだかは見ないので、数を書いた返事は、係を呼んでいなくても通ります
- 催促しないとき: `read_masked` を呼ぶ前の停止(手順1 で利用者に聞いたときなど)、催促のあとの続き(`stop_hook_active` が true)、入力や記録が読めないとき。読めないときは止めない側に倒します。`guard-raw` は逆に止める側に倒します
- 止まり続けません: 催促の続きでは `stop_hook_active` で何もしません。Claude Code にも連続8回の上限があります(道具を呼ぶと数が戻ります)
- 記録の遅れ: 会話の記録は非同期に書かれ、Stop の時点で今のターンの分がまだ無いことがあります。`read_masked` の呼び出しがまだ記録に無ければ、催促は出ません。返事の文は記録でなく Stop の入力の `last_assistant_message` から読みます
- 余分に出るとき: 手順の途中で利用者に聞いて止まったとき、数を表の列など別の書き方で書いたとき、点検のあとに別の話をしたとき(記録に `read_masked` が残るので)は、1回余分に催促が出ることがあります。Skill の frontmatter の hook は呼んだときに登録され、会話の終わりまで残るので、別の話の返事ごとに出ることもあります。催促が出ると、`claude -p` や評価の回では1ターン増えます
- 確かめたこと: 判断の関数の試験(`tests/unit/check-done.test.mjs`)と、合成の記録を渡して端末で6通り動かした1回だけです。Skill の frontmatter に Stop を置く例は公式のページに無く、Claude Code に登録されるか、`${CLAUDE_PLUGIN_ROOT}` が解けるかはまだ確かめていません。登録されないときは、同じコマンドを `hooks/hooks.json` の Stop に移します

## Claude Code での作り方
この節に書く仕組み(自走キット・hook・subagent・機能の一覧)は、開始前に作ったもので、このリポジトリには入っていません(審査の対象外です)。作品の働きの説明ではなく、作り方の記録として書いています。

この作品は、Claude Code(Claude のコーディング用のエージェント)が、1つずつの機能を短いセッションで作り、人は決めることがあるときだけ答える形で作りました。開発の仕組み(自走キット)は開始前に用意し、主催者の案内に従ってリポジトリの外に置いています(キットのファイルはこのリポジトリに入れていません)。仕組みの働きは次のとおりです。

- 自走のループ: 外のスクリプトが、機能の一覧(目標と確かめ方を書いた表)から、まだ通っていない機能を1つ選ばせ、そのたびに新しいセッションを立ち上げます。長い1つの会話で文脈が崩れるのを避けるためです。各セッションは、前回の記録と git の履歴を読んでから着手し、確かめ方の出力を示して通ったときだけ「通った」にして commit します。同じ機能が3回通らなければ止まって人に知らせます。判断できないこと・仕様と食い違うことは、推測で埋めずに人への質問として書き、止まります
- hook(Claude Code の決まった時点で動くスクリプト):
  - セッションの開始: 今の進み具合と前回の記録の終わり・人への質問の一覧を、セッションに入れ直す
  - 道具を使う前: プロジェクトの外や鍵のファイルへの読み書き、固定した受け入れテストの書き換え、push・履歴の消去などの危ない git の操作、許していない Web への接続を止める
  - 返答を終える前: 全部の試験と整合の点検が通らないうちは、終わらせずに作業を続けさせる
  - あわせて、コマンドは Claude Code の sandbox の中で動かし、外への通信と書き込みの場所を絞った
- subagent(役目を分けた別のエージェント):
  - reader: 法令や国交省の資料の決まった箇所を、書いてあるまま写す係(長い資料を主の文脈に入れないため)
  - checker: 規則表と原文だけを見て、抜き書きが原文にあり規則を支えているかを確かめる係(作った側の説明は見ない)
  - critic: 区切りの終わりに、作った側の説明と仕込み表を見ずに、ツールの出力と規則表の誤りを探す係。指摘と対応は `docs/critic.md`
- 受け入れテストの固定: 人が承認した受け入れ条件から、最初に受け入れテスト(`tests/acceptance/`、21 ファイル)を書き、その後は指紋(ハッシュ)で固定しました。エージェントはこのテストを直せず、合わないと思ったときは人に聞きます。テストに合わせた決め打ちを防ぐためです
- 仕込みの評価: 作る係とは別の係が、架空の書類3件(`fixtures/`)に抜けと誤りを仕込み、その一覧(仕込み表)はリポジトリと PC の外に置きました。作る係は仕込み表を読みません

### プラグインの評価のケース(plugin/evals/)
Claude Code のプラグイン(上の「Claude Code のプラグイン」)を入れたときと入れないときで、点検の答えがどう違うかを人が比べるための材料です。2026-11-03 に、2ケース × あり・なし × 3回 = 12回走らせました(結果の表と合計は `docs/評価.md` の 5)。見落としは あり 5/30(すべて止まった1回)・なし 0/30 で、止まった1回のほかはどちらも0です。条番号と抜き書きが取得した原文にある割合は、あり 72.9%・79.3%、なし 47.1%・18.8% でしたが、下の限界のとおりこの数え方はプラグインの側に有利で、回数も各3回だけなので、良し悪しは言い切れません。採点は人が見直していません。

- `cases/E1_しおかぜ町下水道/`・`cases/E2_あおば台共同住宅/`: 違反を仕込んだ架空の書類(`raw/`)と `case.json`。書類は評価のために新しく作ったもので、`fixtures/`(見本と初めて見る書類)とは別です。`case.json` には、Claude Code に渡す頼み方(`prompt`)、採点基準(`criteria`)、仕込んだ抜け・誤り(`planted`。各ケース5件。何が・根拠の条・当たりと数える語の組)を書いています。仕込みの根拠の条は、すべてプラグインが取得した原文にあります(試験で確かめています)
- `rubric.json`: 採点基準の定め。見落とし率(仕込みのうち、どの指摘にも当たらなかった数の割合)、条番号の正しさ(答えの条番号のうち、取得した原文にある数の割合)、抜き書きの正しさ(条番号を書いた行の「」の中の文のうち、挙げた条の原文にそのまま含まれる数の割合)
- `score.mjs`: 答えを採点するスクリプト。外部と通信せず、Claude も呼びません

走らせ方(人が行う。1回ずつ):
1. 空の作業フォルダを作り、ケースの `raw/` だけをそこへ写す(`case.json` は写さない。答えを見せないため)
2. プラグインあり: その作業フォルダで `claude --plugin-dir <このリポジトリ>/plugin` を開き、`case.json` の `prompt` を渡す。プラグインなし: 同じ作業フォルダの写しを別に作り、`--plugin-dir` を付けずに開いて同じ `prompt` を渡す(プラグインなしでは `raw/` の守りも置き換えも無いので、架空の書類だけで行う)
3. 返ってきた指摘を作業フォルダの外のファイル(例 `答え_E1_あり_1.md`)に保存する
4. `node plugin/evals/score.mjs plugin/evals/cases/E1_しおかぜ町下水道 答え_E1_あり_1.md` で採点する(`--json` で JSON)。出力の当たり外れを人が見直す
5. 同じことを何回か繰り返し、回数と数字をそのまま `docs/評価.md` に書く(答えは毎回変わるので、1回の差で良し悪しを言い切らない)

費用: 走らせると、1回ごとに Claude Code が Claude のモデルを使います。利用者のプランの使用量か、API の料金がかかります(ケース2件 × あり・なし × 回数の分)。作る係のループは Claude を呼んでいません。

限界:
- 当たりの数え方は粗いです。指摘を区切りの行で1件ずつに分け、1件の中に決めた語の組がそろえば当たりと数えます。語が違えば当たっていても見落としに数え、別の点の指摘でも語がそろえば当たりに数えます。出力の「当たった」「見落とし」は人が見直してください
- 条番号の正しさは、その条・項・号が取得した原文にあるかだけを見ます(上の Skill の条番号の確かめと同じ部品)。指摘の中身が条に合っているかは数えません。プラグインなしの答えは、取得していない条を正しく挙げても「原文に無い」に数えられるので、この数字はプラグインの側に有利です
- 仕込みの書き手と、プラグイン(Skill の手順・条の要約)の書き手は同じ係です。仕込みが Skill の見る所に寄っているおそれがあります
- ケースは2件・仕込みは10件だけで、言い過ぎ(仕込んでいない所の指摘)は数えません
- `cases/` のケースはこのツールの独自の形で、`claude plugin eval` では走りません。上の手で行う走らせ方を使います。公式の評価のケースは別に `E1-trace-masked/`・`E2-trace-masked/` があり、走らせ方は [docs/評価.md の 7](評価.md#7-公式の評価のケースe1-の名前がやりとりの記録に出ないか) にあります
- 走らせた12回のうち、プラグインありの1回(E1 の3回目)は、書類のファイル名が分からず、点検を始めずに人に聞いて終わりました(raw/ の一覧を見る操作がフックで止まりました。そのときプラグインの MCP の道具は `read_masked` だけで、ファイルの一覧を返す道具はありませんでした。その後 F23a で、名前の一覧だけを返す `list_masked` を足し、Skill の手順に「書類の名前が分からないときは list_masked」と書きました。足した後の評価は走らせていません)。ありの見落とし 5 件はすべてこの1回のものです
- 書類はプラグインのフォルダ(`plugin/evals/`)の中にあり、`case.json` に仕込みの一覧があります。走らせるときは作業フォルダをプラグインのフォルダの外にしてください(Claude Code がプラグインのフォルダを読みに行けば、仕込みの一覧を見られるおそれがあります)

### 法令の原文(e-Gov 法令 API)

`node scripts/fetch-sources.mjs` で e-Gov 法令 API(v2)から取得し、本則の条だけを `data/sources/` に保存した。一覧と取得日は `data/sources/index.json`。

取得に使った API: `https://laws.e-gov.go.jp/api/2/law_data/<法令ID>?response_format=xml`。どの改正の版かは index.json の `revisionId` にある(法令ID_施行日_改正の法令番号)。画面・印刷・CSV では、根拠の抜き書きの近くに「取得日 2026-11-02・版 2025年12月12日施行の改正までの条文(e-Gov の版 …)」のように出す(`src/source-version.mjs`。施行日は revisionId の真ん中の8桁から作る)。国交省の資料は index.json の `edition`(資料の題名にある版の表示「令和8年3月」「令和7年2月1日から適用」を写した値)を「… の版」と出し、無いときは「版の表示なし」と出す。CSV は「取得日」の隣に「版」の列がある。施行規則 第14条の2 は、ほかの条の取得日と版を変えないように `node scripts/fetch-sources.mjs --law kisoku` で、その法令だけを取得した(版 324M50004000014_20261001_508M60000800082)。抜き書きは第1項(記載事項)の柱書き・号・号の細分(イ・ロ…)・その下の (１)〜(６) ごとに `data/quotes.json` に入れ、`subitem`(号の細分)まで原文と照らす。第2項(添付書類)・第3項・第4項(電磁的記録)は原文に入っているが、抜き書きにしていない。法令は改正されるので、使う前に e-Gov で原文を確かめ直すこと。
