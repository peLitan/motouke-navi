# 画面の見た目の方針

画面(`index.html`)の配色・文字・配置の決めごとです。外部のフォント・画像・CDN は使いません(画面は外部と通信しません)。

## 文字
- 文字は端末にある書体を順に選ぶ(BIZ UDPGothic → 游ゴシック → メイリオ → sans-serif。無い端末では sans-serif に落ちる)。外部のフォントは読まない。色は `src/ui/shell.html` の `:root` の変数で決め、大きさは 16・19・24・32px の4段にする(2rem は入口の題だけ。幅 40rem 以下では 1.5rem)
- 本文は 16px(1rem)以上・行間 1.7。補足・脚注・入力欄・ボタン・整形済みの文も 16px より小さくしない(印刷だけは紙の大きさで 10.5pt。まとめの紙の出典と根拠の行だけ 9pt)
- 文字と地の色のコントラストは、色を決めたすべての決まりで 4.5:1 以上(単体の試験 tests/unit/ui-type.test.mjs で計算して確かめる)
- 文字と地の組は、`tests/unit/ui-contrast.test.mjs` で WCAG の式で計算する(F83a10)。自分の地を持たない字は、親の薄い地(白・灰・薄い青・語の印の地)のどれに乗っても本文 4.5:1・大きい字 3:1 以上にする。触れたときの地も元の字の色で見る。`--check` の字は白地でぎりぎりなので、白地を決めた決まりの中でだけ使う
- 結論の言葉(要る・確認が要る・要らない)は太字にする

## 配色
- 地は白、文字は濃い灰色。強調は濃い青(主のボタンと上の帯)。黒い 3px の枠は対応表の警告の1つだけにする
- 結論の札は、白地に色の枠・太字の印・言葉で示し、色だけで区別しない。白黒で印刷しても印と言葉で分かる
- 選んでいるボタンは、薄い地・2px の枠・太字に加えて「✓ 選択中」の字を CSS で出す
- 見本の帯は白地に主の色の枠。薄い青の地は、触れた・選んでいるボタンにだけ使う
- 表は見出しの下を黒い 2px、行を灰色の 1px にし、回数の列は右寄せにする

| 結論 | 記号 | 文字の色 | 地の色 | 枠の色 | 文字と地のコントラスト |
|---|---|---|---|---|---|
| 要る | ● | #ce0000(赤系) | #fff | #ec0000 | 4.5:1 以上(単体の試験で計算して確かめる) |
| 確認が要る | ! | #927200(黄系) | #fff | #b78f00 | 同上 |
| 要らない | ✓ | #197a4b(緑系) | #fff | #259d63 | 同上 |
| 未回答 | ? | #595959(灰色) | #fff | #949494(破線) | 同上 |

- 色の値の出所: 多くはデジタル庁デザインシステムの npm パッケージ `@digital-go-jp/design-tokens`(MIT)から借りた。`--primary-dark` と `--mark-weak` はこの道具で決めた。この画面はデジタル庁が作ったものではない
- 文字と地は 4.5:1 以上、文字以外の線は 3:1 以上、押す所は高さ 44px 以上(単体の試験 `ui-visual` が CSS の書いた値から計算して確かめる。押せない物の線は対象の外。描いた結果は見ていない)
- 件数は数字と長さで見せ、色の濃さを量に使わない

## 土台(F43a)
- 上に作品名の帯(`.topbar`)を置く。地は端まで塗り、中身は `.wrap`(幅 60rem)にそろえる。幅は body ではなく `.wrap` で決める。帯の地と字は `--bar-bg`・`--bar-ink` で、印刷では白地に黒にする。紙の帯は作品名だけにし、副題は出さない(まとめでも全部でも。画面には出す)
- 断り書き(`#disclaimer`)は入口と「1 条件を入れる」では帯のすぐ下に、印(丸に !)つきの1行として出す。文は変えない。太い枠はやめたので(作者の承認 2026-11-05)、濃い字の太字にして弱くしない。折りたたみと段の外に置き、紙にも出す。「2 結果を見る」と「3 書類を確かめる」では、同じ語で短くした1行「指摘の候補です。最終の確認は担当者と発注者との協議で行ってください(くわしく)」(`#notice-more`。同じ印と太字)を出し、断り書き・できること・見ていない法令の1行・法令の一覧・通信しない表示を、この行を開くまで画面から外す(F83a4)。紙はどの段でも今の全文
- カードは白地、`--line` の 1px の縁、角 12px、薄い影 `--shadow`(印刷では消える)。結果(`.result`)・まとめ(`.summary`)・入札前の入力(`.form`)・「ここからは別の道具」(`.other-tools`)・入口のボタンに使う。見本の案D の薄い線(#d8d8d8)は白地で 3:1 に届かないので使わない。影は縁の代わりにしない
- 角は部品 8px、カード 12px、番号の丸 50% の3種。余白(margin・padding・gap)は 4・8・12・16・24・32・40px の段階だけを使う(単体の試験 `ui-visual` が総なめにする)
- 進み具合(`#steps`)は番号の丸を線でつなぎ、3つの段の名前を全部出す。段の切り替えはボタンのまま。入口を選ぶまでは灰色の破線の丸と灰色の字で押せない(主の色の輪と字を使わず、指の形も「押せない」の形も出さない普通の矢印にする。F83a6)、押せる段は実線の丸、今の段は塗った丸と太字。今より前の段の線は主の色(CSS の `:has()`。効かないブラウザでは線が灰色のままで、番号と名前は読める)。線は枠線で描くので、3:1 と印刷の黒の検査に掛かる

## 配置
- 結論を先に置く: 「確認する」や「まず見本で試す」のあと、入力の確かめ(下の節)の「この内容で結果を見る」で段2「結果を見る」を開いて、先頭に数字のカード3つと「次にすること」のカードを出す(`#result-top`。`renderResultTop`)。そのあとの並びは 要る項目のカード → 受注後の段取り → 安全の法令の候補 → 確認が要る点と未回答 → まとめ(`#summary`)
- まとめは、受注したら要るものの件数、確認が要る点の数、台帳と目次の開くカード、入れた条件の開くカードを持つ。条件が変わった・読めないの知らせは、先頭のカードとまとめの両方に出す。項目の一覧(`.summary-items`)は画面では上のカードと重なるので、紙にだけ出す
- まとめの各行は、ページの中のリンクで詳しい結果へ移る。飛ぶ先が閉じた折りたたみの中なら開く(`openPanelForLink`)

## 入力の確かめ(F43d)
- 結果の前に `#panel-confirm` を置く。「確認する」と「まず見本で試す」はここへ進み、公告の読み込みは残りの欄を入れて「確認する」を押すとここを通る。もう受注した方の入口は条件を入れないので通らない
- 進み具合には段を足さず、「1 条件を入れる」の中の画面に数える(案D のとおり)。3つの段の名前と番号は変えない
- 判定に使う条件を全部の行(8行)で並べる。行ごとに値・出どころ(公告・見本・手入力・最初の値。入れていない行は「入れていません」)・「変更」のボタン。行の枠とボタンは静的な HTML にあり、中身は `src/ui/confirm.mjs` が作る
- 公告から入れた値は「推定」の札と「確認が要ります」を出す。公共か民間かと工事の種類は公告の語からの読み取り、請負代金は予定価格(上限の見込み)からの読み替えで、どれも公告にそのまま書いてある値ではないため。抜き書きは 80 字で切って出す
- 読み込んだあとに値を変えた行は手入力に戻す。出どころは読み込んだときの値と今の値を比べて決める(メモリだけに持つ)
- 読み込みの記録が無く、画面を開いたときに `collect(doc)` で取った値のままの行は「最初の値(変えていません)」と出す(F59。工種の土木と閲覧の措置の「講じない」)。`confirmRows` は DOM に触らないので、最初の値は引数で受ける。読み込みの記録がある欄は、最初の値に戻しても手入力のまま。一度変えて同じ値に戻した欄は見分けない
- まだ答えていない行(state が unset)には、結果と同じ「? 未回答」の札を付ける(F59)
- 工事の種類が建築一式で工種が土木のままなら、工種の行に注意を出す。公告の読み込みで同じ形になったときは知らせの行にも1文を足す。段1 には「変更」のボタンが無いので、知らせの文は「工種」の欄と書く。値は変えない(F59)
- 金額の欄が読めないときは、欄を離れたとき(`change`)に欄の下の `p.field-error` に文を出し、`aria-invalid` を付け、`aria-describedby` の hint の後ろに誤りの id を足す。直れば誤りの id だけを外す。打っている途中(`input`)には出さない。「分からない」の印を付けたときと、公告の読み込みで値が替わったときも同じ関数で付け直す(F59)
- 金額の欄を億・万・千円・百万円の単位つきで読めたときは、同じ関数で誤りの文の直後の `p.field-read` に「n円 として読みました」を出し、`aria-describedby` の後ろにその id を足す。字は補足の色にせず本文の `--ink` にする(千円の取り違えで額が1000倍ずれるのに気づけるように)。打ち直している間(`input`)は古い値なので消し、欄を離れたときにまた出す。数字だけの値・読めない値・「分からない」の印のときは出さない(F83a7)
- 「変更」は段1 の入れ直す欄へ戻って焦点を移す。元請けか下請けかは選んでいる印へ、金額の「分からない」に印があればその印へ戻す。直したら「確認する」でまた確かめへ進む
- 判定は「確認する」でも走り、結果は隠れた段に書く。「この内容で結果を見る」でも走らせ直す(画面の値と結果を食い違わせない)。読めない金額は行に値と直し方を出す
- 紙には出さない(入れた条件はまとめの開くカードにあるため)。幅 40rem 以下では項目名を上の行へ置き、「この内容で結果を見る」を下の帯にする

## 結果の画面(F43c)
- 数字のカードは 要るものの候補(● 項目)・確認が要る点(! 件)・安全の法令の候補(▲ 件)の3つ。カード全体がリンクで、押すとその節へ飛ぶ(`#bid-result`・`#open-items`・`#safety-fold`)。説明に「候補」を入れ、言い切りに読めないようにする。安全は要るものの数に混ぜず、問いに答える前は 0 と言わず「−」にする。要るものの候補も、未回答が残り決まった「要る」の項目が無いときは「● 0」と言わず「−」と「質問に答えると出ます」にする(F62b。全問に答えて要る項目が無いときの 0 は決まった数なので「● 0」のまま)。40rem 以下では行の形にし、4つ目「受注後の段取りの例」を足す
- 安全のカードは主の色を使わない(青は「問題なし」「押せる字」に読めるため)。印 ▲ と灰色の上の線で示す
- 「次にすること」は1つだけ出す。順は 読めない欄を直す → もう一度「確認する」 → 元請けの実績の知らせ(公告の文に当たったときだけ) → 未回答に答える → 確認が要る点を確かめる → 書類を確かめる。元請けの実績を未回答より先に置くのは、参加の条件なので、質問に答える前に知らせるためです。確認が要る点の文は判定の文をそのまま使う。紙には出さない
- 要る項目は `.item` のカードにし、見えるのは結論の札と名前と、要るの項目だけ次にすることの1行。この1行(`.item-next`)は結果全体で1つのカードの「次にすること」とは別で、札のすぐ下、`details.basis` の外に出す。文は `src/ui/next-steps.mjs` の `NEXT_STEPS` に、判定の `note` の語句だけで書き、期限・書類名・宛先・数字・括弧の根拠を足さない(`note` が名詞で終わる行は語句に「があるかを確かめる」を続ける)。例外は専任の1行だけで、`note` の語句のままでは読めないので、項目の名前の語で「技術者を専任で置く必要があるかを確かめる」とする。`note` と根拠の折りたたみは変えない。例外の有無はどの行にもほぼ同じに付いて区別にならないので行には書かず、例外のある行があるときだけ、節の頭の1行の後ろに「例外は「根拠を見る」の「例外・読み方の注意」にあります。」を足す。後ろの決まった文「当てはまるかは「根拠を見る」で確かめてください。」は字を小さくせず、補足の色 `--ink-2` で下げる。理由・入れた条件・根拠・例外・確かめ先は `details.basis`「根拠を見る: 条の名前」の中に、今までの順で置く(根拠が無い項目は「理由を見る」)。並びは 要る → 確認が要る → 未回答 → 要らない。紙では開いて、カードの枠を行の線に戻す
- 確認が要る点の答えで結論が変わる項目は、判定の `checks` の `changes: true` を見て「この「要る」は、確認が要る点の答えで変わることがあります」と閉じずに書く。今は専任の項目だけ。結論が変わらない確認(許可の種類の入力の確かめなど)には「この項目には確認が要る点があります」とだけ書く
- 専任の確認の文は、確かめることを先に書き、続けて現場を兼ねる特例の一文を置く(`sharedSiteSentence`)。金額と現場の数は施行令 第28条・第30条の抜き書きの漢数字から読む(`sharedSiteLimit`)。第28条の金額が掛かるのは第26条第3項ただし書の第1号だけで、第2号(監理技術者を補佐する者を専任で置く)には金額の条件が無いので、金額以上でも特例全部が無いとは書かない
- 専任が要ると出たときの技術者の選び方の1行(`dedicatedPersonCheck`)と税抜きの知らせは、項目 `dedicated` の確認が要る点にする。別の key にすると、結論の出た項目について確かめる点として数えられない(`pointsNote`)。1行の根拠は第26条第5項と運用マニュアルの抜き書き(`q-mlit-manual-koyo`)で、3か月の雇用は法令の条ではないと文に書く。第26条第5項は第2項の監理技術者の定めで、マニュアルの原文は「元請の」と書くので、下請け(`direct === false`)には出さない。民間は専任かを確かめる段階で、3か月の定めも掛からないので、1行にせず確かめの文の中に資格の文だけを足す(項目1つに点1つのまま)。
- 税抜きの知らせは、結論が「要らない」で、入れた額の1.1倍が専任の境目以上になるときだけ出す。金額を超えても専任とは限らないので「変わることがあります」と書く。小数の誤差を避けて `amount * 11 >= line * 10` で比べる。判定そのものは入れた額のままで、`changes` の印で「答えで変わることがある」と項目に出す。下請け(`direct === false`)の専任の文は、確かめる相手を公告でなく元請けにする。
- 開くカードは `details.open-card`・`#bid-fold`・`details.schedule-table`・`details.safety-fold` の4種を同じ形にする。件数は見出しに出し、「開く ▾」「閉じる ▴」は CSS で足す(紙には出さない)。まとめの中の2つは、描き直しても開いたままにする
- 結果の3つの欄(`#bid-result`・`#schedule-result`・`#safety-result`)はカードを中に持つので、枠の無い `.result-plain` にする
- スマホ(40rem 以下)で下に止まる帯は段ごとに1つ(確かめの段は「この内容で結果を見る」、結果の段は「次へ: 3 書類を確かめる」)。同時には出ない。`position: sticky` の決まりは `.step-next` の1つ。それぞれの段の最後の行が止まるので、下まで動かせば本文は隠れない。パソコンの幅では止めない。焦点のある物が帯の裏に隠れないよう、`html` の `scroll-padding-bottom` は帯の高さと焦点の輪を足した分以上にする。この余白は画面が動くときにしか効かないので、押した後に上の文で物が動く所(`#export-status` の下のボタン、`#rules-status` の下のファイルの入力、`#schedule-notice` の下の「和歌山県の例」)は、文を書いた後に焦点のある物を画面に入れ直す。背の低い画面で知らせと焦点の両方が入らないときは焦点を優先する

## 折りたたみと印刷
- 根拠の原文の抜き書きは折りたたみ(details)に入れ、最初は閉じる。見出しは「根拠: 建設業法 第26条第2項」のように中身が分かる言葉にする
- 受注後の段取りの表は「受注後の段取り(○件)」の折りたたみに入れる。件数と段ごとの件数の1行は折りたたみの外に出す
- 結論(要る・確認が要る・要らない、候補の名前)と断り書きは閉じない。理由は閉じてよい(F43c)。未回答の説明と、結論が変わることがある知らせは閉じない
- 段取りの「発注者の仕様書では」の欄に書いた行がある区切りと大きな折りたたみは、描き直しても開く(書いたことが閉じた中に隠れないように)。注意は欄より先に出す。紙には textarea ではなく隣の .print-only の文を出す(長い文が切れないように)
- 表の中に折りたたみを入れない。段取りの表の「根拠」の列は箇所の名前だけにし、原文は表の下の「根拠: 共通仕様書の原文」にまとめる
- 印刷のボタンは2つ。「PDF で保存・印刷」(#print-btn)はまとめ、「全部を印刷する」(#print-all-btn)は全部を出す。PDF は押して開く印刷の画面で作る(画面が自分で PDF を作る部品は入れない)
- 「全部を印刷する」とブラウザのメニューからの印刷(Ctrl+P)では、ボタンと操作の部分を消し、折りたたみをすべて開く(ボタンと beforeprint で開き、afterprint で印刷のために開いたものだけを閉じ直す)。beforeprint はどちらのボタンから来たか分からないので、クラスと題名に触らず、メニューからの印刷は全部のままにする
- 「PDF で保存・印刷」は、結果が無いとき(確認の前・条件を変えた後)は印刷の画面を開かず知らせだけを出す。空の PDF を残したと思い込ませないため。「全部を印刷する」は、もう受注した方の段取りの一覧を結果無しで紙にする道として、知らせを書いて開く
- ボタンから印刷する間だけ、body に print-brief(まとめのとき)を付け、document.title を「Motouke Navi まとめ YYYY-MM-DD」の形にする(PDF の既定のファイル名になる。見本のときは「見本」を入れる)。まとめは summary-docs・summary-conditions の2つだけを開く。afterprint で全部を元に戻す
- まとめの紙に出すのは、版と印刷した日時、断り書き、見ていない法令・資料の1行、確認が要る点と未回答、まとめ(要るものの候補の項目名と札、台帳と目次の点検の数、入れた条件)、使った法令と資料、使った資料の表示、確認の記録。切り替えは body の print-brief で、印刷の CSV の最後の規則だけで行う(描く関数は変えない)
- まとめの紙に出さないのは、頭の説明と見ている法令の一覧、条件の入力、入札前の確認の詳しい結果、受注後の段取り、安全の法令の候補、書類の点検、別の道具、数字のカード(まとめの数の繰り返し)、次にすること(確認が要る点と同じ文になる)。リンク先の欄があることを前提にした文(.human の結びと、ul.print-only の次の段落)も隠す。段取りの書き込みと記載事項の「確認した」は全部の紙にだけ出る
- まとめの紙は、結果の見出しの下に説明の行(#brief-note)を置き、何が入っていないかと全部を印刷した版があることを伝える。画面と全部の紙には出さない(.brief-only)。並びは画面のまま変えない(並べ替えると PDF の読み上げの順とずれるおそれがある)ので、入れた条件が「まとめ」の最後にあることも説明の行に書く
- まとめの紙でも、確認が要る点の根拠の折りたたみ(.basis)は隠さず、閉じたまま見出しの1行を残す。条番号が紙に残り、原文の抜き書きは全部の紙に出す
- まとめの紙の字の大きさと余白は pt で書く(rem は画面の基準のままで、紙の 10.5pt に連動しない)。2列にはしない(出典と足の文は1件が長く、高さが縮まない)。紙の足(footer)の字はまとめでも全部でも 10.5pt。開いたカードの見出しの開閉の字は、[open] 付きの規則でも消して紙に出さない
- まとめの紙は見本の工事で A4 3枚以内を目標にする。枚数を減らすために紙から消す物は無い。出典の一覧と「根拠を見る」の行を 9pt・行間 1.3 にし(8pt より小さくしない)、折りたたみの見出しの押す所の高さと余白、まとめの中のリンクの余白を紙で外す。どれも body.print-brief の下だけで、全部の紙の字と余白は変えない
- まとめの紙では、カードの見出しが紙の一番下に残って表と分かれないよう、カードの枠(details.open-card)を中で切らない。1枚に入らないカードの表は行の境で紙をまたげる。これも body.print-brief の下だけで、全部の紙の切れ目は変えない
- 書き出しの知らせ(#export-status)は案内の直下に置き、書いたら scrollIntoView で画面に入れる(幅の狭い画面で、押したボタンから離れて見えないままにしない)
- 印刷では、用紙を A4(公共工事の書類の大きさ)、余白を 15mm にし、文字と線の色を黒、塗りを白にする(確信の弱い語の印の地は残す)。結果の札は黒の枠で残り、未回答の札は破線で見分ける
- 知らせの行は紙に出さない。ただし、台帳・記載事項・目次の結果が前のものだと伝える3つの行と、置き換えの漏れの注記は残す(紙だけを見る人に要るため)。台帳と目次の行には件数も入るので、件数も紙に出る
- まとめはほかの結果と同じカードにする。全部を中央寄せにしない(左寄せ)
- 幅の狭い画面(30rem 以下)では、入れた条件の一覧を項目名と値の縦並びにする

## 狭い画面(スマホ)
- 幅 320〜400px でも、ページ全体は横に動かない。幅は枠線と余白を含めて数え(box-sizing: border-box)、長い URL などは折り返す
- 入力欄は枠の幅まで(max-width: 100%)。文を貼る欄は幅いっぱい
- 表は名前つきの枠(.table-scroll)に入れ、その枠の中だけで横に動かす。キーボードでも枠に来て動かせる。段取りの表は 40rem(640px)以下で行ごとのカードにし、各欄の前に列の名前(data-label)を出す。印刷では枠で切らずに全部を出す
- 段取りの表は区切り(着手まで・施工中・完成・引き渡し)ごとに畳める。最初の区切りだけ開いて出す
- 進み具合は 40rem 以下でも3つの段を横に等しい幅で並べ、字は小さくせず、丸の下に名前を全部出す(長い名前は2行に折り返す)。読み上げには aria-label で番号と名前を渡す
- 置き換えの前と後の2列は、40rem(640px)以下で1列(前の下に後)にする。見本のボタンも幅いっぱいにする
- ボタン・文字の入力欄・選ぶ欄・折りたたみの見出しは、指で押せる高さ(44px)にする。丸・四角の印は 20px にし、ラベルを押しても選べる。指の端末(`pointer: coarse`)では 48px にする
- ボタンの既定は副の形(白地・主の色の枠と字)。主の形(塗り)は「確認する」「台帳を点検する」「目次を点検する」「次へ: 3 書類を確かめる」と入口の「まず見本で試す」だけ。押せないときは灰色、選んでいる方(`aria-pressed`)は薄い地・2px の枠・太字
- 「入口に戻る」は段と同じ形にしない。段の列の下の行に灰色の枠で置く
- 文字の入力欄とファイルの欄も高さ 44px にする。焦点はどの部品でも同じ2重の輪(内が黄、外が黒)で、`outline` は焦点のためだけに使う
- body の最初に「本文へ飛ぶ」リンク(`.skip-link`。`#main` へ。F83a10)を置く。いつもは画面の外にあり、焦点が来たときだけ出る。読み上げから隠さないよう `display: none` にしない。印刷には出さない。`h2` の焦点の輪もほかの部品と同じ決まりで、スクリプトが焦点を移す見出し(`#confirm-title`)に効く
- この環境にはブラウザが無いので、幅は実際には測っていない。CSS の決まりと、画面が出す表がすべて枠に入っていることを単体の試験 tests/unit/ui-mobile.test.mjs で確かめる

## 注意の枠と言葉
- 太い黒の枠(`.warning-box`)は1つだけにする: 対応表の書き出しの警告(元の名前が入ったファイル)
- ほかの注意(ファイルの読み方・置き換えの漏れ・AI の候補の断り・国の直轄の例など)は、灰色の左線の注記にする。枠が多いと、本当に大事な注意が目立たなくなるため
- 入札前の確認の入力欄には、名前の横に ※必須 / ※任意 を付け、欄の下に1行の補足を置く(aria-describedby でつなぐ)。補足は意味の説明にとどめ、「必ず」「義務」のような言い切りはしない。※必須の欄が空なら、その欄を使う項目は「判断できない」になる
- CSV の説明は利用者の言葉で書く(「Excel で開ける CSV として、この端末に保存します(外へは送りません)」)。BOM などの用語は画面に出さない
- 入札前の確認の CSV の「注意」の行(`src/export.mjs` の `stage1Rows` の最後の行)の説明の列に、道具の版(印刷の頭の `data-version`。`build.mjs` の `toolVersion` が `{{VERSION}}` に入れる値で、画面の足の `#tool-version` と同じ)・書き出した日時(ISO 8601、端末の時刻と時差)・入れた条件の要約(`readBidForm` の値のうち入っている物を、まとめの枠の `SUMMARY_FIELDS` の名前で並べる)・根拠の出典の URL(重なりを除く)を改行でつないで足す(F83a8)。取得日の列には日時を入れない。参加の条件の本文は写さない。行の数と列は変えない

## 聞き方と結果の順(F14f)

- 入札前の確認の ※必須 の質問(発注者・元請けか下請けか・工事の種類・請負代金の見込み・下請けの総額・元請けの許可の種類・置ける技術者の資格)に「分からない」を置く。選ぶ欄は選択肢、元請けか下請けかは丸、金額は欄の横の四角の印。
- 答えの状態は3つ(答えた・分からない・未回答)。判定(src/bid-check.mjs・src/taicho.mjs)には「分からない」も未回答も同じ null を渡し、推測で埋めない。
- 項目の状態は 要る(●)・要らない(✓)・確認が要る(!)・未回答(?)。決められなかった項目のうち、未回答の質問を使うものを「未回答」、それ以外(「分からない」を選んだ・原文の上で確かめることがある)を「確認が要る」にする。決められた項目は、ほかの質問が未回答でもそのまま。項目が使う質問の表は src/ui/answers.mjs の ITEM_DEPS。
- 未回答の質問が1つでも残るうちは、結果とまとめの枠に「仮の一覧」と出す。
- 各項目は 結論 → 理由(判定の文と、項目が使う質問の答え)→ 根拠の条(折りたたみ)→ 確かめ先 の順。確かめ先は、根拠の原文に相手が書かれているものだけ(特定建設業の許可 → 許可をした国土交通大臣か都道府県知事(建設業法 第3条第1項)、公共の台帳と写し → 発注者(入契法 第15条第2項)、民間の台帳 → 発注者の閲覧(建設業法 第24条の8第3項))。原文に相手が無い項目は「出していません」と書く。
- 冒頭に「このツールが見ている法令・資料」(data/sources/index.json の題名を build.mjs が並べる)と「見ていない法令・資料」(条例・契約書・特記仕様書・国土交通省令など)を出す。
- 画面の下の「使った法令と資料(取得日)」は、build.mjs の `sourcesHtml` が index.json から法令・資料ごとに1行へまとめて組み立てる(名前・取得日・版・URL。行の順は index.json で最初に出る順、条は数の順、法令の版は施行日だけ)。条ごとの取得日・版(e-Gov の版の番号の全文)・URL は `#sources-detail` の折りたたみの中に残し、この折りたたみは紙に出さない。紙には1行の一覧と改正の注意の段落が出る。e-Gov の版の番号の全文は、根拠の抜き書きの近くの「取得日・版」の行にも出る。
- 入札前の確認の結果の最後(段取りの下)に「確認が要る点と未回答の質問」の一覧を出す。印刷にも出る。
- 結果の画面(段2)では、閉じた折りたたみの外に同じ文を2回出さない(20字以上)。2回目からは `seeAbove` の「→ 上の「節の名前」を見てください」の1行にし、文は `.print-only`・`.print-inline` で紙にだけ残す。紙は節ごとに読むので文を減らさない(まとめの紙は入札前の確認の節を出さず、最後の一覧を出す)。
- 確認が要る点の全文の置き場は最後の一覧(`#open-items`)で、画面でも全文を出す。「確認が要る点を見る」・数のカード・項目の「確認が要る点」のリンクはどれもここへ飛ぶ(F85a)。入札前の確認の節は、画面では件数の見出しと説明の行(`#bid-checks`)と「→ 下の「確認が要る点と未回答の質問」を見てください」の1行にし、点の文と根拠は `.print-only` で全部の紙にだけ残す。参照が節の間を往復しないよう、この点の参照は一方向にする。
- 「次にすること」のカードの副題は、確認が要る点の枝では「1件目: 点の名前」の短い1文で、点の文を入れない。枠が縦に伸びて画面から出るのを防ぐ。元請けの実績・未回答・金額の失敗の枝の文はそのまま。
- 確認が要る点の根拠が項目のカードの根拠と同じときは、最後の一覧の点の下の折りたたみを紙にだけ出す。カードごとの「当てはまるかは…」は節の頭に1回にし、紙はカードごとに残す。安全の候補は、同じ文の2つ目の候補を最初の候補への参照にする。
- まとめの状態ごとの数は「項目」、確認が要る点の数は「件」で数える。札「確認が要る」は項目があるときだけ出す(0項目と書くと、上の数の「確認が要る点」の件数と並んで食い違って見える)。ほかの札は 0 でも出す。確認が要る点は、まとめ・入札前の確認・最後の一覧のどれも `needsCheckPoints` の数を出す(未回答の項目は除く)。結論の出た項目についての確認があると「確認が要る」の項目の数より多くなるので、そのときは「うち n件は、結論の出た項目について確かめる点です」と添える
- 印刷の版の最後(出典の表示の下)に「確認した人」「日付」の空欄の表を出す(画面には出さない。.print-only)。

## 説明の畳み方(F37b)
- 押す物の隣の説明は1行までにし、2行目からは折りたたみ(details.fold)に入れる。7問の説明は「説明」の折りたたみに入れ、id と aria-describedby は残す(閉じていても読み上げの説明として渡る)。見出しは同じ「説明」なので、aria-label で欄の名前を添える。説明の最初の文に法令の語がある欄(工種・請負代金の見込み・下請けの総額・元請けの許可の種類・置ける技術者の資格)は、法令の語を使わない平易な1文(`#欄の id-plain`)を折りたたみの外に置き、今の説明は見出し「くわしく」の中に一字も変えずに残す。平易な1文は今の説明の語だけで作り、新しい法令の言い分を足さない。`aria-describedby` は平易な1文 → くわしい説明の順。
- 題から段の前までの折りたたみの外の文字は 450字以内(単体の試験 ui-fold で数える)。
- 畳まないもの: 断り書き・見ていない法令の1行・通信しない表示(この3つは入口と「1 条件を入れる」と紙で。結果と書類の段の形は上の「断り書き」の項のとおり)・国の直轄の例の注記・出典の表示・取得日。A の置き換えの漏れの注意、対応表と辞書のファイルの注意、B の AI の候補の注意は、「ここからは別の道具」を開けば内側の折りたたみを開かずに見える。
- A・B は閉じた1つの折りたたみ #other-tools に入れる。B の結果は今までどおり印刷に出るので、折りたたみ全体には no-print を付けず、見出しと A に付ける。
- 読み込んだ表を使うときは国の例の説明(#schedule-about・#plan-about)が隠れるので、空にならないよう折りたたみの見出しごと隠す。

## 入口と段の切り替え(F37a)
- 入口(F43b)の題は「まず、どう始めますか」。3つの大きなタイル(まず見本で試す/条件を入れる/公告を読み込む)を同じ大きさで並べ、見本を先頭の主の形(塗り)にする。絵は飾りなので `aria-hidden`。選ぶとタイルを隠し、「入口に戻る」で戻せる。
- マウスのある端末では、ファイルの8つの口の行と公告のタイルにファイルをドラッグして置ける(タイルの案内の1行は `::after` で、置いた瞬間に種類を確かめ、違えば入口に留まる。枠の外に置いたら今見えている段の口の知らせの欄に書く)。指の端末とスマホ幅では枠も案内も出さず、ボタンで選ぶ
- 読み込み中(F83a9): ボタンで選んでもドラッグして置いても、読む前にその口の知らせの欄へ「「<ファイル名>」を読んでいます…」を出し `aria-busy="true"` を付ける(.xlsx・.docx・.pdf は1秒を超えることがあるため)。読み終わったら(失敗でも、例外でも)外し、読む関数の文に替わる。PDF の口は今までどおり「(3/8頁)」の進み具合に書き換える。段1 の口は順番に読むので、欄ごとに数え、最後の1つが終わったときに外す。読んだ後の知らせにはファイルの名前が入る
- 置き換えは1回で走らせる(区切ると名前が区切りをまたいで漏れる)。20,000字を超える文では、先に `#mask-status` へ「置き換えています…」と `aria-busy` を出し、`setTimeout(0)` で一度画面に手を返してから走らせる。20,000字以下は今までどおりその場で走る
- ファイルの欄のボタン(`input[type="file"]::file-selector-button`)は、ほかのボタンと同じ枠・色・角丸・高さ・触れたときの地にする。焦点の輪は input の焦点の決まりで欄の全体に付けるので、部品ごとの焦点の決まりは足さない
- 公告のタイル(F83a6 から主の文は「公告を読み込む」、副の文は「公告の PDF か、AI がまとめた条件のファイル(.json)を選ぶ」。1280 幅で主の文が1行に収まる短さにした)は、段1 の折りたたみ「公告から拾った条件を読み込む」を開き、ファイルの欄へ焦点を移す。読み込みが動いているので「準備中」とは書かない。ファイルを選ぶ窓を自動では開かない(何のファイルかを読んでから選べるように)。
- 段3 の「目次を PDF・Word から読む」(`#plan-file`、F82d)は、読んだ文から頁の区切りの行だけを除いて `#plan-input` に入れる。`tidyPdfText` は通さない(1行に1つの見出しの目次がつながる)。点検は走らせず、`#plan-result` も変えない(読み取りの崩れと本文の見出しを人が見てから押す)。台帳の点検は目次の欄も突き合わせるので、欄へ入れたら `input` を出して前の点検の結果を古くする。読む間に別のファイルが来たら後のファイルを読み、前の結果は捨てる。台帳と体系図の欄には PDF の口を足さない(欄の形に合わず、表の行がずれて別の会社の値が入るおそれがある)

## 押したあとの知らせ(F38d)
- 「確認する」「見本で試す」「もう受注した」のあとは、結果の見出しの直下の1行(#bid-status。aria-live)に、起きたことと次の一手を出す。印刷には出さない。トーストは作らない。
- 文に入っている知らせの行は、太字に主の色の 4px の左線。注記(灰色の左線)と見本の帯の文は太字にしないので、色だけで分かれない。
- 結果の大きな枠(#bid-result など9つ)には aria-live を付けず、1行の知らせと短い注記(#mask-decoy・#mask-residual)だけに残す(F57)。実際の読み上げソフトでは確かめていない。
- 枠の代わりに、知らせの行に件数を書く(F57)。#bid-status は頭のあとに「要る n項目。」(数はカードと同じ。カードが「−」のときは「＊ 仮の結果が出ました(未回答 n問)。」にして「要る 0項目」を書かない。F62b)、#check-status は「台帳の候補 n件。」(判断できない点があれば「、判断できない m件」を足す)、#plan-status は「目次の候補 n件。」、#schedule-status は「段取り n行。」。比べていないときは 0 と書かない(目次の表が無ければ「目次: 判断できない n件。」、段取りの表が無ければ書かない)。台帳・目次が空のとき、点検が途中で止まったときも、この行に「＊」で出す。
- 頭の ✓ は結果が出たときだけ文の中に書く。金額を読めない・条件が変わった・途中で止まったときは「＊」で始め、何をすればよいかを書く。
- 失敗の知らせには `data-kind="error"` を付け、左線と字を `--need` の色にする(F58a)。色・線・言葉の3つで示す。付けるのは、ファイルを読めなかった文(8つの口・入口のタイル・枠の外に置いたとき)と、#bid-status の「金額の欄を読めませんでした」「判定の途中で止まりました」。印の CSS が「× 失敗: 」を足すので、この2つの文の頭に「＊」は書かない(F85d)。「条件が変わりました」「仮の結果が出ました」は失敗ではないので、「＊」のままで付けない。`#check-status` などほかの知らせの行は、この周では付けていない。
- 赤(`--need`)は「要る」・必須の欄・失敗の知らせの3つに使うので、色を変えずに印と文字でも見分ける(F83a15)。要るは札の ●、必須は枠つきの札「※必須」、失敗は頭の「× 失敗: 」。「× 失敗: 」は CSS の `::before` で足すので、知らせの文そのものと読み取れる textContent は変わらない。付けるのは `data-kind="error"` の行・`.fail-head`(`renderErrors` の見出し)・`.field-error`・`.summary-error`・`span.errors`。入力が空の知らせ(`renderEmptyInput`)と「条件が変わりました」は失敗ではないので付けない。印刷でも残る。実物の画面と読み上げソフトでは確かめていない。
- 印は文では判定しない。読む関数が `false` を返したら付け、知らせの欄に書き直すたびに `writeNotice`(`src/ui/notice.mjs`)が外す。`div.errors` も同じ色と線にそろえる。台帳・目次が空のときは失敗ではないので、知らせの行のほかは次の手の1文だけを、線の無い形で結果の枠に出す(F85h)。確かめの画面の行の中の `span.errors` は色だけ。見た目は実物の画面では確かめていない。
- 読めなかった文には、キーの名前・欄の id・部品の名前を出さない(F58b)。欄は確かめの画面の行の名前(`CONFIRM_ROWS` の label)で書く。辞書と対応表は、形と版のどちらが違っても「このツールで書き出した…ではないか、版が違います」の1つの文にし、何行目・何番目かは残す。対応表を辞書の口で読んだときの案内も残す。.docx・.xlsx を解凍できないブラウザの文は「文字をコピーして貼り付けてください」にする(置き換えの口は .csv を読まず、台帳の口は .xlsx しか読まないので、2つの口に共通して使える手はこれだけ)。「JSON」の語は JSON として読めないときの文に残っている
- 金額を読めないまま欄を離れるか「確認する」を押すと、その欄に aria-invalid を付けて 2px の枠にし、欄の下に文を出す(F59)。直すと外す。誤りの文の一覧はこれまでどおり結果の欄に出す。
