# 画面の見た目の方針

画面(`index.html`)の配色・文字・配置の決めごとです。外部のフォント・画像・CDN は使いません(画面は外部と通信しません)。

## 文字
- 文字は端末の標準の書体(`system-ui, "Hiragino Sans", "Yu Gothic UI", Meiryo, sans-serif`)。外部のフォントは読まない
- 本文は 16px(1rem)以上・行間 1.7。補足・脚注・入力欄・ボタン・整形済みの文も 16px より小さくしない(印刷だけは紙の大きさで 10.5pt)
- 文字と地の色のコントラストは、色を決めたすべての決まりで 4.5:1 以上(単体の試験 tests/unit/ui-type.test.mjs で計算して確かめる)
- 結論の言葉(要る・確認が要る・要らない)は太字にする

## 配色
- 地は白、文字は濃い灰色。強調の枠は濃い青(見本のボタン)と濃い紺(まとめの枠の左の太線)
- 結論の印は、色・記号・言葉の3つで示し、色だけで区別しない

| 結論 | 記号 | 文字の色 | 地の色 | 枠の色 | 文字と地のコントラスト |
|---|---|---|---|---|---|
| 要る | ✕ | #991b1b(赤系) | #fee2e2 | #b91c1c | 4.5:1 以上(単体の試験で計算して確かめる) |
| 確認が要る | ! | #713f12(黄系) | #fef3c7 | #a16207 | 同上 |
| 要らない | ✓ | #14532d(緑系) | #dcfce7 | #15803d | 同上 |

- 件数は数字と長さで見せ、色の濃さを量に使わない

## 配置
- 結論を先に置く: 「確認する」や「見本で試す」のあと、1. の入力欄のすぐ下に「まとめ」の枠を出す。中身は、受注したら要るものの件数と一覧、施工体制台帳が要るか、段取りの件数、台帳の点検の候補の数、目次の抜けの候補の数、入れた条件(項目名と値の一覧)
- まとめの各行は、ページの中のリンクで詳しい結果へ移る。根拠の条は各結果の折りたたみの中に置く

## 折りたたみと印刷
- 根拠の原文の抜き書きは折りたたみ(details)に入れ、最初は閉じる。見出しは「根拠: 建設業法 第26条第2項」のように中身が分かる言葉にする
- 受注後の段取りの表は「受注後の段取り(○件)」の折りたたみに入れる。件数と段ごとの件数の1行は折りたたみの外に出す
- 結論(要る・確認が要る・要らない、候補の名前)と断り書きは閉じない
- 表の中に折りたたみを入れない。段取りの表の「根拠」の列は箇所の名前だけにし、原文は表の下の「根拠: 共通仕様書の原文」にまとめる
- 印刷では、ボタンと操作の部分を消し、折りたたみをすべて開く(beforeprint で開き、afterprint で印刷のために開いたものだけを閉じ直す)
- まとめの枠は角を丸めず、左の太線で区切る。全部を中央寄せにしない(左寄せ)
- 幅の狭い画面(30rem 以下)では、入れた条件の一覧を項目名と値の縦並びにする

## 狭い画面(スマホ)
- 幅 320〜400px でも、ページ全体は横に動かない。幅は枠線と余白を含めて数え(box-sizing: border-box)、長い URL などは折り返す
- 入力欄は枠の幅まで(max-width: 100%)。文を貼る欄は幅いっぱい
- 表は名前つきの枠(.table-scroll)に入れ、その枠の中だけで横に動かす。キーボードでも枠に来て動かせる。段取りの表は5列あるので、潰さずに横に動かす。印刷では枠で切らずに全部を出す
- 置き換えの前と後の2列は、40rem(640px)以下で1列(前の下に後)にする。見本のボタンも幅いっぱいにする
- ボタン・文字の入力欄・選ぶ欄・折りたたみの見出しは、指で押せる高さ(44px)にする。丸・四角の印は 20px にし、ラベルを押しても選べる
- この環境にはブラウザが無いので、幅は実際には測っていない。CSS の決まりと、画面が出す表がすべて枠に入っていることを単体の試験 tests/unit/ui-mobile.test.mjs で確かめる

## 注意の枠と言葉
- 目立つ枠(太い橙の線と淡い地)は2つだけにする: 冒頭の必須の断り書きと、対応表の書き出しの警告(元の名前が入ったファイル)
- ほかの注意(ファイルの読み方・置き換えの漏れ・AI の候補の断り・国の直轄の例など)は、灰色の左線の注記にする。枠が多いと、本当に大事な断り書きが目立たなくなるため
- 入札前の確認の入力欄には、名前の横に ※必須 / ※任意 を付け、欄の下に1行の補足を置く(aria-describedby でつなぐ)。補足は意味の説明にとどめ、「必ず」「義務」のような言い切りはしない。※必須の欄が空なら、その欄を使う項目は「判断できない」になる
- CSV の説明は利用者の言葉で書く(「Excel で開ける CSV として、この PC に保存します(外へは送りません)」)。BOM などの用語は画面に出さない

## 聞き方と結果の順(F14f)

- 入札前の確認の ※必須 の質問(発注者・元請けか下請けか・工事の種類・請負代金の見込み・下請けの総額・元請けの許可の種類・置ける技術者の資格)に「分からない」を置く。選ぶ欄は選択肢、元請けか下請けかは丸、金額は欄の横の四角の印。
- 答えの状態は3つ(答えた・分からない・未回答)。判定(src/bid-check.mjs・src/taicho.mjs)には「分からない」も未回答も同じ null を渡し、推測で埋めない。
- 項目の状態は 要る(✕)・要らない(✓)・確認が要る(!)・未回答(?)。決められなかった項目のうち、未回答の質問を使うものを「未回答」、それ以外(「分からない」を選んだ・原文の上で確かめることがある)を「確認が要る」にする。決められた項目は、ほかの質問が未回答でもそのまま。項目が使う質問の表は src/ui/answers.mjs の ITEM_DEPS。
- 未回答の質問が1つでも残るうちは、結果とまとめの枠に「仮の一覧」と出す。
- 各項目は 結論 → 理由(判定の文と、項目が使う質問の答え)→ 根拠の条(折りたたみ)→ 確かめ先 の順。確かめ先は、根拠の原文に相手が書かれているものだけ(特定建設業の許可 → 許可をした国土交通大臣か都道府県知事(建設業法 第3条第1項)、公共の台帳と写し → 発注者(入契法 第15条第2項)、民間の台帳 → 発注者の閲覧(建設業法 第24条の8第3項))。原文に相手が無い項目は「出していません」と書く。
- 冒頭に「このツールが見ている法令・資料」(data/sources/index.json の題名を build.mjs が並べる)と「見ていない法令・資料」(条例・契約書・特記仕様書・国土交通省令など)を出す。
- 入札前の確認の結果の最後(段取りの下)に「確認が要る項目と未回答の質問」の一覧を出す。印刷にも出る。
- 印刷の版の最後(出典の表示の下)に「確認した人」「日付」の空欄の表を出す(画面には出さない。.print-only)。

## 最初の1画面(F14g)
- 幅1280・高さ900の最初の1画面に、題・断り書き・できること3行・「見本で試す」のボタン・段階の表示が入るようにした。並びは 題 → 断り書き → できること → 見ていない法令・資料の1行 → 法令の一覧(閉じた折りたたみ) → 1. の見出し → 見本の枠
- 題は何のツールか分かる名前にした。作品名は利用者が決めた「Motouke Navi」で、画面の題は「Motouke Navi(はじめての元請けの確認ツール)」と日本語の説明を添えた。ページの title も同じ
- 「このツールが見ている法令・資料」と「見ていない法令・資料」の2つの一覧は結論ではないので、見出しで中身が分かる折りたたみ(最初は閉じる)に入れた。印刷では開く(F14c の決まり)
- 「見ていない法令・資料があります(条例・契約書・特記仕様書・省令など)。別に確かめてください。」の1行は折りたたみの外に置き、常に見せる(印刷にも出す)
- 「この画面は外部と通信しません」の注記は消さず、見本の枠のすぐ下へ移した
- 題の文字は 1.75rem にし、冒頭の余白を詰めた。本文は 16px のまま
- この環境にはブラウザが無いので、高さは実測していない。単体の試験 tests/unit/ui-firstview.test.mjs が、画面の HTML の文と CSS の値から各ブロックの高さを多めに見積もる(和文1字1em、英数字0.6em、行末の禁則の分を1字、上下の余白は重ねずに足す)。今の見積もりは 711px

## 台帳の記載事項の表(F16c)
- 置き場所は「2. 施工体制台帳の点検」の候補の下。「台帳を点検する」で候補と一緒に出す(ボタンを増やさない)。候補と表は別に動かし、片方が止まっても片方は出す
- 表の冒頭に太字で「チェックはこのツールの判定ではありません。確認した人と日付は印刷の版に書いてください」、その下に「記載事項に空がある・判断できないまで。適法かは判定しない」の注記と、値・空・判断できない・確認したの件数
- 列は 確認した・相手・記載事項・状態・台帳の値・理由・根拠の場所。表は .table-scroll の枠に入れ(min-width 48rem)、狭い画面では枠の中だけで横に動く。根拠の原文は表の中に入れず、表の下の折りたたみ「根拠: 建設業法施行規則 第14条の2 第1項の原文(○件)」に事項ごとに1回だけ出す(F14c)
- 「空」の行は状態の文字を太字にする(色だけに頼らない)。「確認した」の欄はチェックの横に「確認した/未確認」の文字を出し、印刷でもチェックの有無が文字で残る。押せる高さは 44px
- チェックは app.mjs の Set にだけ持ち、ブラウザに保存しない。表を描き直してもチェックとフォーカスは残す。台帳の文が変わったら書き出しを止め、点検し直したときに文が違えばチェックを消す
- 国交省のチェックリストは参考の1行(題名・URL・取得日)だけ。リンクにしない(画面は外へつながない)。文は写さない

## 確かめてほしい語(F17c)
- 置き場所は「A. 文の置き換え」の前・後の2列の下。規則だけで見つけた語(対応表の行に rule があるもの)を、後の欄で <mark> の印にする。未確認は黄の地に太い下線と枠、「置き換える」は灰の地、「残す」は青の地で元の語を出す(色だけに頼らず、下線と枠・選ぶ表の「状態」の文字でも分かる)
- 選ぶ表は .table-scroll の枠に入れる。列は 記号・種類・元の語・見つけ方・状態・選ぶ。ボタンは「置き換える」「残す」の2つで、選んだ方は aria-pressed="true" と太字・枠
- 「未確認の語があります(○件)」は「元に戻す」の見出しのすぐ上の注記(.note・太字・role="status")。未確認が0なら hidden にする。目立つ枠(.disclaimer)は増やさない
- 選びは mask-app.mjs の Map(記号 → 置き換える/残す)にだけ持ち、ブラウザに保存しない。ボタンは描き直すたびに作り直すので、表の枠(#mask-review)でクリックを受ける

## 辞書のファイル(F19a)
- 置き場所は「A. 文の置き換え」の足した語の一覧(#dict-list)のすぐ下。灰色の左線の注記(.note。#dict-file-note)で、ブラウザに保存しないこと・書き出せること・元の名前が入っていることを先に書き、その下に「辞書を書き出す」のボタンと「辞書を読み込む」のファイルの欄を並べる。知らせは #dict-file-status(aria-live)。目立つ枠(.disclaimer)は増やさない
- 書き出しは、知らせの欄に「このファイルには元の名前が入っています…」を出し、確認の窓(confirm)で同じ文を見せてから保存する。やめたら保存しない。ファイル名は「置き換えの辞書_日付.json」
- ファイルの形は { format: "mask-dict", version: 1, notice, terms: [{ word, kind }] }。記号・対応表は入れない(対応表のファイル format: "mask-map" とは別)
- 読み込みは今の足した語に加える。中身をすべて確かめてから加え、おかしければ理由を出して何も変えない
