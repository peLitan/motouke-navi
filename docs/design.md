# 画面の見た目の方針

画面(`index.html`)の配色・文字・配置の決めごとです。外部のフォント・画像・CDN は使いません(画面は外部と通信しません)。

## 文字
- 文字は端末にある書体を順に選ぶ(BIZ UDPGothic → 游ゴシック → メイリオ → sans-serif。無い端末では sans-serif に落ちる)。外部のフォントは読まない。色は `src/ui/shell.html` の `:root` の変数で決め、大きさは 16・19・24・32px の4段にする(2rem は入口の題だけ。幅 40rem 以下では 1.5rem)
- 本文は 16px(1rem)以上・行間 1.7。補足・脚注・入力欄・ボタン・整形済みの文も 16px より小さくしない(印刷だけは紙の大きさで 10.5pt)
- 文字と地の色のコントラストは、色を決めたすべての決まりで 4.5:1 以上(単体の試験 tests/unit/ui-type.test.mjs で計算して確かめる)
- 結論の言葉(要る・確認が要る・要らない)は太字にする

## 配色
- 地は白、文字は濃い灰色。強調は濃い青(主のボタンと上の帯)。黒い 3px の枠は対応表の警告の1つだけにする
- 結論の札は、白地に色の枠・太字の印・言葉で示し、色だけで区別しない。白黒で印刷しても印と言葉で分かる
- 選んでいるボタンは、薄い地・2px の枠・太字に加えて「✓ 選択中」の字を CSS で出す
- 見本の帯は白地に主の色の枠。薄い青の地は、触れた・選んでいるボタンにだけ使う
- 表は見出しの下を黒い 2px、行を灰色の 1px にし、回数の列は右寄せにする

| 結論 | 記号 | 文字の色 | 地の色 | 枠の色 | 文字と地のコントラスト |
|---|---|---|---|---|---|
| 要る | ● | #ce0000(赤系) | #fff | #ec0000 | 4.5:1 以上(単体の試験で計算して確かめる) |
| 確認が要る | ! | #927200(黄系) | #fff | #b78f00 | 同上 |
| 要らない | ✓ | #197a4b(緑系) | #fff | #259d63 | 同上 |
| 未回答 | ? | #595959(灰色) | #fff | #949494(破線) | 同上 |

- 色の値の出所: 多くはデジタル庁デザインシステムの npm パッケージ `@digital-go-jp/design-tokens`(MIT)から借りた。`--primary-dark` と `--mark-weak` はこの道具で決めた。この画面はデジタル庁が作ったものではない
- 文字と地は 4.5:1 以上、文字以外の線は 3:1 以上、押す所は高さ 44px 以上(単体の試験 `ui-visual` が CSS の書いた値から計算して確かめる。押せない物の線は対象の外。描いた結果は見ていない)
- 件数は数字と長さで見せ、色の濃さを量に使わない

## 土台(F43a)
- 上に作品名の帯(`.topbar`)を置く。地は端まで塗り、中身は `.wrap`(幅 60rem)にそろえる。幅は body ではなく `.wrap` で決める。帯の地と字は `--bar-bg`・`--bar-ink` で、印刷では白地に黒にする
- 断り書き(`#disclaimer`)は帯のすぐ下に、印(丸に !)つきの1行として常に出す。文は変えない。太い枠はやめたので(作者の承認 2026-11-05)、濃い字の太字にして弱くしない。折りたたみと段の外に置き、紙にも出す
- カードは白地、`--line` の 1px の縁、角 12px、薄い影 `--shadow`(印刷では消える)。結果(`.result`)・まとめ(`.summary`)・入札前の入力(`.form`)・「ここからは別の道具」(`.other-tools`)・入口のボタンに使う。見本の案D の薄い線(#d8d8d8)は白地で 3:1 に届かないので使わない。影は縁の代わりにしない
- 角は部品 8px、カード 12px、番号の丸 50% の3種。余白(margin・padding・gap)は 4・8・12・16・24・32・40px の段階だけを使う(単体の試験 `ui-visual` が総なめにする)
- 進み具合(`#steps`)は番号の丸を線でつなぎ、3つの段の名前を全部出す。段の切り替えはボタンのまま。入口を選ぶまでは破線の丸で押せない、押せる段は実線の丸、今の段は塗った丸と太字。今より前の段の線は主の色(CSS の `:has()`。効かないブラウザでは線が灰色のままで、番号と名前は読める)。線は枠線で描くので、3:1 と印刷の黒の検査に掛かる

## 配置
- 結論を先に置く: 「確認する」や「まず見本で試す」のあと、入力の確かめ(下の節)の「この内容で結果を見る」で段2「結果を見る」を開いて、先頭に数字のカード3つと「次にすること」のカードを出す(`#result-top`。`renderResultTop`)。そのあとの並びは 要る項目のカード → 受注後の段取り → 安全の法令の候補 → 確認が要る点と未回答 → まとめ(`#summary`)
- まとめは、受注したら要るものの件数、確認が要る点の数、台帳と目次の開くカード、入れた条件の開くカードを持つ。条件が変わった・読めないの知らせは、先頭のカードとまとめの両方に出す。項目の一覧(`.summary-items`)は画面では上のカードと重なるので、紙にだけ出す
- まとめの各行は、ページの中のリンクで詳しい結果へ移る。飛ぶ先が閉じた折りたたみの中なら開く(`openPanelForLink`)

## 入力の確かめ(F43d)
- 結果の前に `#panel-confirm` を置く。「確認する」と「まず見本で試す」はここへ進み、公告の読み込みは残りの欄を入れて「確認する」を押すとここを通る。もう受注した方の入口は条件を入れないので通らない
- 進み具合には段を足さず、「1 条件を入れる」の中の画面に数える(案D のとおり)。3つの段の名前と番号は変えない
- 判定に使う条件を全部の行(8行)で並べる。行ごとに値・出どころ(公告・見本・手入力。入れていない行は「入れていません」)・「変更」のボタン。行の枠とボタンは静的な HTML にあり、中身は `src/ui/confirm.mjs` が作る
- 公告から入れた値は「推定」の札と「確認が要ります」を出す。公共か民間かと工事の種類は公告の語からの読み取り、請負代金は予定価格(上限の見込み)からの読み替えで、どれも公告にそのまま書いてある値ではないため。抜き書きは 80 字で切って出す
- 読み込んだあとに値を変えた行は手入力に戻す。出どころは読み込んだときの値と今の値を比べて決める(メモリだけに持つ)
- 「変更」は段1 の入れ直す欄へ戻って焦点を移す。元請けか下請けかは選んでいる印へ、金額の「分からない」に印があればその印へ戻す。直したら「確認する」でまた確かめへ進む
- 判定は「確認する」でも走り、結果は隠れた段に書く。「この内容で結果を見る」でも走らせ直す(画面の値と結果を食い違わせない)。読めない金額は行に値と直し方を出す
- 紙には出さない(入れた条件はまとめの開くカードにあるため)。幅 40rem 以下では項目名を上の行へ置き、「この内容で結果を見る」を下の帯にする

## 結果の画面(F43c)
- 数字のカードは 要るものの候補(● 項目)・確認が要る(! 件)・安全の法令の候補(▲ 件)の3つ。カード全体がリンクで、押すとその節へ飛ぶ(`#bid-result`・`#open-items`・`#safety-fold`)。説明に「候補」を入れ、言い切りに読めないようにする。安全は要るものの数に混ぜず、問いに答える前は 0 と言わず「−」にする。40rem 以下では行の形にし、4つ目「受注後の段取りの例」を足す
- 安全のカードは主の色を使わない(青は「問題なし」「押せる字」に読めるため)。印 ▲ と灰色の上の線で示す
- 「次にすること」は1つだけ出す。順は 読めない欄を直す → もう一度「確認する」 → 未回答に答える → 確認が要る点を確かめる → 書類を確かめる。確認が要る点の文は判定の文をそのまま使う。紙には出さない
- 要る項目は `.item` のカードにし、見えるのは結論の札と名前だけ。理由・入れた条件・根拠・例外・確かめ先は `details.basis`「根拠を見る: 条の名前」の中に、今までの順で置く(根拠が無い項目は「理由を見る」)。並びは 要る → 確認が要る → 未回答 → 要らない。紙では開いて、カードの枠を行の線に戻す
- 確認が要る点の答えで結論が変わる項目は、判定の `checks` の `changes: true` を見て「この「要る」は、確認が要る点の答えで変わることがあります」と閉じずに書く。今は専任の項目だけ。結論が変わらない確認(許可の種類の入力の確かめなど)には「この項目には確認が要る点があります」とだけ書く
- 開くカードは `details.open-card`・`#bid-fold`・`details.schedule-table`・`details.safety-fold` の4種を同じ形にする。件数は見出しに出し、「開く ▾」「閉じる ▴」は CSS で足す(紙には出さない)。まとめの中の2つは、描き直しても開いたままにする
- 結果の3つの欄(`#bid-result`・`#schedule-result`・`#safety-result`)はカードを中に持つので、枠の無い `.result-plain` にする
- スマホ(40rem 以下)で下に止まる帯は段ごとに1つ(確かめの段は「この内容で結果を見る」、結果の段は「次へ: 3 書類を確かめる」)。同時には出ない。`position: sticky` の決まりは `.step-next` の1つ。それぞれの段の最後の行が止まるので、下まで動かせば本文は隠れない。パソコンの幅では止めない

## 折りたたみと印刷
- 根拠の原文の抜き書きは折りたたみ(details)に入れ、最初は閉じる。見出しは「根拠: 建設業法 第26条第2項」のように中身が分かる言葉にする
- 受注後の段取りの表は「受注後の段取り(○件)」の折りたたみに入れる。件数と段ごとの件数の1行は折りたたみの外に出す
- 結論(要る・確認が要る・要らない、候補の名前)と断り書きは閉じない。理由は閉じてよい(F43c)。未回答の説明と、結論が変わることがある知らせは閉じない
- 段取りの「発注者の仕様書では」の欄に書いた行がある区切りと大きな折りたたみは、描き直しても開く(書いたことが閉じた中に隠れないように)。注意は欄より先に出す。紙には textarea ではなく隣の .print-only の文を出す(長い文が切れないように)
- 表の中に折りたたみを入れない。段取りの表の「根拠」の列は箇所の名前だけにし、原文は表の下の「根拠: 共通仕様書の原文」にまとめる
- 印刷では、ボタンと操作の部分を消し、折りたたみをすべて開く(beforeprint で開き、afterprint で印刷のために開いたものだけを閉じ直す)
- 印刷では、余白を 15mm にし、文字と線の色を黒、塗りを白にする(確信の弱い語の印の地は残す)。結果の札は黒の枠で残り、未回答の札は破線で見分ける
- 知らせの行は紙に出さない。ただし、台帳・記載事項・目次の結果が前のものだと伝える3つの行と、置き換えの漏れの注記は残す(紙だけを見る人に要るため)
- まとめはほかの結果と同じカードにする。全部を中央寄せにしない(左寄せ)
- 幅の狭い画面(30rem 以下)では、入れた条件の一覧を項目名と値の縦並びにする

## 狭い画面(スマホ)
- 幅 320〜400px でも、ページ全体は横に動かない。幅は枠線と余白を含めて数え(box-sizing: border-box)、長い URL などは折り返す
- 入力欄は枠の幅まで(max-width: 100%)。文を貼る欄は幅いっぱい
- 表は名前つきの枠(.table-scroll)に入れ、その枠の中だけで横に動かす。キーボードでも枠に来て動かせる。段取りの表は 40rem(640px)以下で行ごとのカードにし、各欄の前に列の名前(data-label)を出す。印刷では枠で切らずに全部を出す
- 段取りの表は区切り(着手まで・施工中・完成・引き渡し)ごとに畳める。最初の区切りだけ開いて出す
- 進み具合は 40rem 以下でも3つの段を横に等しい幅で並べ、字は小さくせず、丸の下に名前を全部出す(長い名前は2行に折り返す)。読み上げには aria-label で番号と名前を渡す
- 置き換えの前と後の2列は、40rem(640px)以下で1列(前の下に後)にする。見本のボタンも幅いっぱいにする
- ボタン・文字の入力欄・選ぶ欄・折りたたみの見出しは、指で押せる高さ(44px)にする。丸・四角の印は 20px にし、ラベルを押しても選べる。指の端末(`pointer: coarse`)では 48px にする
- ボタンの既定は副の形(白地・主の色の枠と字)。主の形(塗り)は「確認する」「台帳を点検する」「目次を点検する」「次へ: 3 書類を確かめる」と入口の「まず見本で試す」だけ。押せないときは灰色、選んでいる方(`aria-pressed`)は薄い地・2px の枠・太字
- 「入口に戻る」は段と同じ形にしない。段の列の下の行に灰色の枠で置く
- 文字の入力欄とファイルの欄も高さ 44px にする。焦点はどの部品でも同じ2重の輪(内が黄、外が黒)で、`outline` は焦点のためだけに使う
- この環境にはブラウザが無いので、幅は実際には測っていない。CSS の決まりと、画面が出す表がすべて枠に入っていることを単体の試験 tests/unit/ui-mobile.test.mjs で確かめる

## 注意の枠と言葉
- 太い黒の枠(`.warning-box`)は1つだけにする: 対応表の書き出しの警告(元の名前が入ったファイル)
- ほかの注意(ファイルの読み方・置き換えの漏れ・AI の候補の断り・国の直轄の例など)は、灰色の左線の注記にする。枠が多いと、本当に大事な注意が目立たなくなるため
- 入札前の確認の入力欄には、名前の横に ※必須 / ※任意 を付け、欄の下に1行の補足を置く(aria-describedby でつなぐ)。補足は意味の説明にとどめ、「必ず」「義務」のような言い切りはしない。※必須の欄が空なら、その欄を使う項目は「判断できない」になる
- CSV の説明は利用者の言葉で書く(「Excel で開ける CSV として、この端末に保存します(外へは送りません)」)。BOM などの用語は画面に出さない

## 聞き方と結果の順(F14f)

- 入札前の確認の ※必須 の質問(発注者・元請けか下請けか・工事の種類・請負代金の見込み・下請けの総額・元請けの許可の種類・置ける技術者の資格)に「分からない」を置く。選ぶ欄は選択肢、元請けか下請けかは丸、金額は欄の横の四角の印。
- 答えの状態は3つ(答えた・分からない・未回答)。判定(src/bid-check.mjs・src/taicho.mjs)には「分からない」も未回答も同じ null を渡し、推測で埋めない。
- 項目の状態は 要る(●)・要らない(✓)・確認が要る(!)・未回答(?)。決められなかった項目のうち、未回答の質問を使うものを「未回答」、それ以外(「分からない」を選んだ・原文の上で確かめることがある)を「確認が要る」にする。決められた項目は、ほかの質問が未回答でもそのまま。項目が使う質問の表は src/ui/answers.mjs の ITEM_DEPS。
- 未回答の質問が1つでも残るうちは、結果とまとめの枠に「仮の一覧」と出す。
- 各項目は 結論 → 理由(判定の文と、項目が使う質問の答え)→ 根拠の条(折りたたみ)→ 確かめ先 の順。確かめ先は、根拠の原文に相手が書かれているものだけ(特定建設業の許可 → 許可をした国土交通大臣か都道府県知事(建設業法 第3条第1項)、公共の台帳と写し → 発注者(入契法 第15条第2項)、民間の台帳 → 発注者の閲覧(建設業法 第24条の8第3項))。原文に相手が無い項目は「出していません」と書く。
- 冒頭に「このツールが見ている法令・資料」(data/sources/index.json の題名を build.mjs が並べる)と「見ていない法令・資料」(条例・契約書・特記仕様書・国土交通省令など)を出す。
- 入札前の確認の結果の最後(段取りの下)に「確認が要る点と未回答の質問」の一覧を出す。印刷にも出る。
- まとめの状態ごとの数は「項目」、確認が要る点の数は「件」で数える。確認が要る点は、まとめ・入札前の確認・最後の一覧のどれも `needsCheckPoints` の数を出す(未回答の項目は除く)。結論の出た項目についての確認があると「確認が要る」の項目の数より多くなるので、そのときは「うち n件は、結論の出た項目について確かめる点です」と添える
- 印刷の版の最後(出典の表示の下)に「確認した人」「日付」の空欄の表を出す(画面には出さない。.print-only)。

## 説明の畳み方(F37b)
- 押す物の隣の説明は1行までにし、2行目からは折りたたみ(details.fold)に入れる。7問の説明は「説明」の折りたたみに入れ、id と aria-describedby は残す(閉じていても読み上げの説明として渡る)。見出しは同じ「説明」なので、aria-label で欄の名前を添える。
- 題から段の前までの折りたたみの外の文字は 450字以内(単体の試験 ui-fold で数える)。
- 畳まないもの: 断り書き・見ていない法令の1行・通信しない表示・国の直轄の例の注記・出典の表示・取得日。A の置き換えの漏れの注意、対応表と辞書のファイルの注意、B の AI の候補の注意は、「ここからは別の道具」を開けば内側の折りたたみを開かずに見える。
- A・B は閉じた1つの折りたたみ #other-tools に入れる。B の結果は今までどおり印刷に出るので、折りたたみ全体には no-print を付けず、見出しと A に付ける。
- 読み込んだ表を使うときは国の例の説明(#schedule-about・#plan-about)が隠れるので、空にならないよう折りたたみの見出しごと隠す。

## 最初の1画面(F14g)
- 幅1280・高さ900の最初の1画面に、帯・断り書き・できることの1行・入口のタイル・段階の表示が入るようにした(できること3つは折りたたみの中。F37b)。並びは 帯 → 断り書き → できること → 見ていない法令・資料の1行 → 法令の一覧(閉じた折りたたみ) → 1. の見出し → 見本の枠
- 題は何のツールか分かる名前にした。作品名は利用者が決めた「Motouke Navi」で、画面の題は「Motouke Navi(はじめての元請けの確認ツール)」と日本語の説明を添えた。ページの title も同じ
- 「このツールが見ている法令・資料」と「見ていない法令・資料」の2つの一覧は結論ではないので、見出しで中身が分かる折りたたみ(最初は閉じる)に入れた。印刷では開く(F14c の決まり)
- 「見ていない法令・資料があります(条例・契約書・特記仕様書・省令など)。別に確かめてください。」の1行は折りたたみの外に置き、常に見せる(印刷にも出す)
- 「この画面は外部と通信しません」の注記は消さず、見本の枠のすぐ下へ移した

## 入口と段の切り替え(F37a)
- 入口(F43b)の題は「まず、どう始めますか」。3つの大きなタイル(まず見本で試す/条件を入れる/公告から拾った条件を読み込む)を同じ大きさで並べ、見本を先頭の主の形(塗り)にする。絵は飾りなので `aria-hidden`。選ぶとタイルを隠し、「入口に戻る」で戻せる。

- 公告のタイルは、段1 の折りたたみ「公告から拾った条件を読み込む」を開き、ファイルの欄へ焦点を移す。読み込みが動いているので「準備中」とは書かない。ファイルを選ぶ窓を自動では開かない(何のファイルかを読んでから選べるように)。
- 「用意するもの」は題とタイルの間に語を並べるだけにする。ボタンでも入力でもないので、枠・地・影・四角の印を付けず、頭の印は「・」。無くても進められることを添える。
- もう受注した人の入口は、タイルの下の小さな下線の字のボタン(`.entry-link`。id は同じ `entry-awarded`)。字は 16px のままで、押す所の高さ 44px は保つ。

- 画面は 1 条件を入れる・2 結果を見る・3 書類を確かめる の段に分け、`#panel-1`〜`#panel-3` の `hidden` で1つずつ見せる。要素は静的な HTML に全部置き、JS では作らない。結果は隠れた段にも書く。
- 段階の表示はボタンで、入口を選ぶまでは押せない(`disabled`)。選んだあとは今いる段の丸だけ塗り、`aria-current="step"` を付ける。
- 「もう受注した」(F37c)は、条件から出した結果がまだ無いときだけ、`buildScheduleDetail(input, table, { all: true })` で全部の行を状態「確かめる」で出す。入力は見ない。段2 の一覧の上に注意と「条件を入れる」を出し、入札前の確認と台帳の欄(`#bid-fold`)は閉じる。「確認する」で通常に戻す。条件から出した結果か入力の誤りの知らせがあるときは、上書きしない。読み込んだ表と和歌山県の例は条件で行が分かれないので、注意の文を変える。全部の行の件数は、条件から出した数ではないのでまとめに入れない。条件の欄を変えても CSV は止めない。
- 見本のあとは、まとめの上に「自分の工事で入れ直す」を出す。見本の値と見本から出た結果を消して段1 を開く。見本のあとに貼り替えた台帳・目次は消さない。
- まとめのリンクの先が隠れた段にあるときは、その段を開いてから移る。印刷は `@media print` で隠れた段も出す。

## 確かめてほしい語(F17c)
- 置き場所は「A. 文の置き換え」の前・後の2列の下。規則だけで見つけた語(対応表の行に rule があるもの)を、後の欄で <mark> の印にする。未確認は黄の地に太い下線と枠、「置き換える」は灰の地、「残す」は青の地で元の語を出す(色だけに頼らず、下線と枠・選ぶ表の「状態」の文字でも分かる)
- 選ぶ表は .table-scroll の枠に入れる。列は 記号・種類・元の語・見つけ方・状態・選ぶ。ボタンは「置き換える」「残す」の2つで、選んだ方は aria-pressed="true" と太字・枠

## 辞書のファイル(F19a)
- 置き場所は「A. 文の置き換え」の足した語の一覧(#dict-list)のすぐ下。灰色の左線の注記(.note。#dict-file-note)で、ブラウザに保存しないこと・書き出せること・元の名前が入っていることを先に書き、その下に「辞書を書き出す」のボタンと「辞書を読み込む」のファイルの欄を並べる。知らせは #dict-file-status(aria-live)。太い枠(.warning-box)は増やさない
- 書き出しは、知らせの欄に「このファイルには元の名前が入っています…」を出し、確認の窓(confirm)で同じ文を見せてから保存する。やめたら保存しない。ファイル名は「置き換えの辞書_日付.json」

## 押したあとの知らせ(F38d)
- 「確認する」「見本で試す」「もう受注した」のあとは、結果の見出しの直下の1行(#bid-status。aria-live)に、起きたことと次の一手を出す。印刷には出さない。トーストは作らない。
- 文に入っている知らせの行は、太字に主の色の 4px の左線。注記(灰色の左線)と見本の帯の文は太字にしないので、色だけで分かれない。
- 頭の ✓ は結果が出たときだけ文の中に書く。金額を読めない・条件が変わった・途中で止まったときは「＊」で始め、何をすればよいかを書く。
- 金額を読めないまま「確認する」を押すと、その欄に aria-invalid を付けて 2px の枠にする。直して押すと外す。誤りの文の一覧はこれまでどおり結果の欄に出す。
