# プロジェクト概要

作品名: Motouke Navi

テーマ: #2「本来、誰にでも届くべきものを。」 — 法令や手続きの壁があって、これまで専門家に頼れる会社しかできなかった確認を、初めて元請けをする小さな会社にも届けます

## 一言で
工事の条件を入れると、入札前の確認・施工体制台帳が要るか・受注後の段取りを、法令と国の仕様書の原文の抜き書きつきで出し、施工体制台帳と施工計画書の目次の抜けの候補も出す、ブラウザで開くだけの道具です。

## 誰の、どんな困りごとか
- 中小の建設会社で、入札・契約・書類を受け持つ担当者
- 「この金額なら特定建設業の許可が要るか」「施工体制台帳は要るか、写しは出すのか」「監理技術者か主任技術者か、専任か」を、そのたびに建設業法・施行令・入契法と国交省の資料を引いて確かめている
- 受注後は、共通仕様書のどの条で、いつ・何を・誰に出すのかを、着手から完成・引き渡しまで追う必要がある
- 台帳や施工計画書の抜けは、監督職員に言われて初めて気づくことがある

## このツールがすること
1. 入札前の確認と台帳の要否: 公共・民間、請負代金、下請けの総額、許可の種類などから、受注したら要るものを、根拠の条(法令名・条・項)と原文の抜き書きつきで出す
2. 受注後の段取り: 国の直轄の例として、着手まで・施工中・完成・引き渡しの段に分け、土木工事共通仕様書(案)令和8年3月の該当箇所と抜き書きつきで一覧にする
3. 施工体制台帳の点検: 貼った台帳(または国交省の作成例の様式の Excel)から、空の欄・技術者の種類・特定建設業・専任の要否の食い違いの候補を出す
4. 施工計画書の目次の点検: 共通仕様書 1-1-1-6 の記載事項と比べ、見当たらない項目を候補に出す
5. 文の置き換え: 外の AI に貼る前に、人名・会社名・住所・電話などを記号に置き換え、戻ってきた文を元に戻す。置き換えた後のファイルだけを Claude の API に送って点検する手元のプログラムと、Claude Code に生のファイルを読ませない設定も付ける

## 大事にしたこと
- 根拠を原文で示す: 規則表の行ごとに原文の抜き書きを持ち、機械で原文と照らす。合わない行は使わない。金額の境目もコードに書かず、抜き書きの文から読む
- 推測で埋めない: 入力から決められないことは「判断できない」と出す。結論は候補で、最後の判断は人がする
- 外へ出さない: 画面は外部と通信せず、入れた内容を保存しない。Claude に送るのは、置き換えた後の中身を利用者が確かめて「送る」と打ったときだけ

## Claude の使い方
- 作り方: Claude Code が、1つずつの機能を短いセッションで作った。受け入れテストは人が承認したものを固定し、エージェントは直せない。原文の写しは reader、抜き書きの照合は checker、区切りの点検は critic という別の subagent に任せ、作る係の自己評価の甘さを補った(README の「Claude Code での作り方」)
- 作品の中: 置き換えた後の書類を Claude の API(`claude-opus-5-5`)に送り、点検の候補を「AI の候補」として、法令の決まりで判定した結果とは別の欄に出す

## 評価
- 受け入れテスト 21 ファイル・110 件が通る
- 規則表の抜き書き 59 件が原文にある(実在率 100%)
- 架空の書類3件に別の係が仕込んだ抜けと誤りを、見つけた・見落とし・言い過ぎで数える(人が採点。`docs/評価.md`)

## 限界
- 指摘の候補であり、抜けが無いことの保証や合否ではない
- 段取りと記載項目は国の直轄の土木工事の例。自治体・民間は発注者の仕様書・契約書で置き換える
- 取り込んだのは一部の条と資料だけ。施行規則・契約約款は入っていない。法令の改正は取得日(2026-11-02)まで
- 文の置き換えの漏れは0にならない
